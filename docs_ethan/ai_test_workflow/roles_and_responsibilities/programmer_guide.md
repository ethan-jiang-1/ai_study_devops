# 程序员角色指导：AI测试资产生产

## 角色定位

您是AI测试资产生产流程中的**技术驱动者**，负责将业务需求转化为AI可理解的指令，并确保生成的测试资产在技术上可行且高质量。

## 核心职责

### 1. 驱动阶段（您的主战场）
- **需求技术分析**：理解业务需求的技术实现路径
- **场景技术拆解**：将业务场景转化为具体的测试场景
- **AI指令设计**：编写高质量的MD格式驱动指令
- **AI协作优化**：通过迭代优化提高AI输出质量

### 2. REVIEW阶段（技术支持）
- **技术可行性确认**：验证测试思路在技术上是否可行
- **技术细节补充**：为非研发人员提供技术背景解释
- **实现复杂度评估**：评估测试实现的技术复杂度

### 3. 反馈阶段（优化执行）
- **反馈技术分析**：分析反馈的技术可行性
- **指令迭代优化**：基于反馈优化AI驱动指令
- **技术方案调整**：调整技术实现方案

## 关键技能要求

### 必备技能
- **业务理解能力**：深度理解业务需求和业务逻辑
- **AI协作技巧**：熟练掌握AI工具的使用方法
- **测试设计能力**：具备系统性的测试设计思维
- **沟通协作能力**：能与非研发人员有效沟通

### 进阶技能
- **领域建模能力**：能够进行业务领域建模
- **架构设计能力**：具备系统架构设计思维
- **质量意识**：具备测试质量标准意识

## 常见问题和解决方案

### 问题1：AI生成的测试思路过于简化
**原因分析**：
- 业务背景描述不够详细
- 技术约束说明不够具体
- 测试要求不够明确

**解决方案**：
- 增加详细的业务流程描述
- 提供具体的技术实现细节
- 明确测试覆盖范围和深度要求

### 问题2：AI不理解复杂的业务规则
**原因分析**：
- 业务规则描述抽象化
- 缺乏具体的业务案例
- 规则之间的关联不清楚

**解决方案**：
- 使用具体的业务案例说明
- 提供业务规则的决策表
- 描述规则之间的依赖关系

### 问题3：技术实现细节不够准确
**原因分析**：
- 技术上下文描述不够详细
- 缺乏技术约束说明
- 没有提供技术架构信息

**解决方案**：
- 提供详细的技术架构描述
- 明确技术栈和框架信息
- 说明关键的技术约束
