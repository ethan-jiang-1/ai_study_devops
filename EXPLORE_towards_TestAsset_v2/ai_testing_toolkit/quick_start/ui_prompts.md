## 🌐 Web网页测试（最常用）

**适用场景**：网站页面、后台管理系统、Web应用界面

### 💡 核心思路
这个提示词专注Web界面：**功能完整 + 用户体验 + 兼容性**
- 详细描述页面元素（让AI知道测什么）
- 强调用户体验要求（响应时间、错误提示）
- 明确兼容性需求（浏览器、设备支持）

### 复制下面的提示词 👇

```
# {页面名称}界面测试用例生成

## 你的角色
你是一个专业的Web界面测试专家，专注于{业务领域}的用户界面测试设计。

## 页面基本信息
- **页面名称**：{页面名称，如：用户登录页面}
- **页面类型**：{登录页/列表页/表单页/详情页等}
- **访问地址**：{页面URL或路径}
- **用户角色**：{谁会使用这个页面，如：普通用户/管理员}
- **业务重要性**：{核心功能/重要功能/一般功能}

## 页面功能描述
### 主要功能
- {功能1}：{详细描述}
- {功能2}：{详细描述}
- {功能3}：{详细描述}

### 页面元素
- **输入框**：{列出所有输入框及其要求}
- **按钮**：{列出所有按钮及其功能}
- **链接**：{列出重要链接}
- **显示区域**：{列出数据展示区域}

## 业务规则
1. {业务规则1，如：用户名不能为空}
2. {业务规则2，如：密码长度8-20位}
3. {业务规则3，如：登录失败3次锁定账户}

## 技术信息
- **前端框架**：{如：Vue.js/React/Angular/原生HTML}
- **浏览器要求**：{支持的浏览器版本}
- **响应式设计**：{是否支持移动端}
- **交互特效**：{是否有动画、弹窗等}

## 用户体验要求
- **页面加载时间**：{加载时间要求}
- **操作响应时间**：{操作反馈时间}
- **错误提示**：{错误提示的位置和内容}
- **成功反馈**：{成功操作的反馈方式}

## 我需要你生成
1. **功能测试用例**（所有功能点的正常和异常测试）
2. **界面布局测试**（不同分辨率、浏览器兼容性）
3. **交互测试用例**（点击、输入、导航等交互）
4. **数据验证测试**（输入验证、数据格式检查）
5. **用户体验测试**（易用性、响应速度、错误处理）
6. **无障碍测试**（键盘操作、屏幕阅读器支持）

每个测试用例包含：
- 测试步骤（详细操作步骤）
- 测试数据（输入的具体数据）
- 预期结果（界面变化和提示信息）
- 优先级（高/中/低）
```

## 💡 界面测试技巧

### ✅ 描述界面时这样更好
- 详细描述用户操作流程
- 明确界面元素的位置和功能
- 说明界面的状态变化
- 提供具体的数据示例

### ❌ 避免这样描述
- 只说"测试登录页面"
- 不提供具体的界面元素
- 忽略用户体验要求
- 缺少错误状态描述

### 🎯 优质描述示例
**好的描述**：
> 用户登录页面，包含用户名输入框（支持邮箱和手机号）、密码输入框（支持显示/隐藏）、记住密码复选框、登录按钮、忘记密码链接。登录失败时在输入框下方显示红色错误提示，成功后跳转到首页。

**差的描述**：
> 登录页面，有输入框和按钮。
