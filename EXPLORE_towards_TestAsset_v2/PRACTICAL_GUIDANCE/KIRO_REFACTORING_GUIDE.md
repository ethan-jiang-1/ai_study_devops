# 贯通流程重构指导文档（临时）

> **重要说明**：本文档为临时重构指导，完成重构后删除

## 🔥 重构背景和目标

### 核心问题
用户反馈发现了框架设计的根本性问题：**当前框架将软件开发阶段当作独立技能训练，而实际应该是贯通流程中的专业分工**。

### 重构目标
- **从独立技能训练 → 贯通流程中的专业分工**
- **从点状技能 → 步步为营的贯通流程**
- **每个阶段的输出成为下一阶段的输入**
- **最终产出完备测试计划驱动AI精确执行**

## 🎯 核心思想转变

### 1. 贯通流程理念
```
错误理解：需求分析 → 设计文档 → 实施规划 → 任务执行（独立技能）
正确理解：需求输出 → 设计输入 → 规划输入 → 执行输入（严格依赖）

核心特征：
- 严格的前置依赖关系
- 质量门禁机制  
- 完整的可追溯性
- 明确的回退机制
```

### 2. TDD正确定位
```
错误定位：TDD贯穿所有阶段，全程强调测试驱动
正确定位：TDD有明确的主场阶段

各阶段TDD职责分工：
├── 需求澄清：验收标准可测试性（不涉及测试实施）
├── 设计文档：可测试性设计，为TDD做准备（但不实施TDD）
├── 实施规划：⭐ TDD的真正主场 - "优先考虑测试驱动开发"
└── 任务执行：严格TDD实施，红绿重构循环

价值：实施规划阶段产出详细测试计划，确保AI精确执行
```

### 3. 阶段职责专业分工
```
需求澄清阶段：专注用户故事和验收标准，不涉及代码探索
设计文档阶段：基于需求输入的架构设计，包含测试策略思考
实施规划阶段：将需求+设计转换为测试驱动的编码任务
任务执行阶段：按tasks.md执行TDD，一次一个任务
```
