## 🔍 基于贯通流程的3步法AI精确执行协作流程

### 第1步：输入理解与任务解析（2-3分钟）
**目标**：准确理解实施规划输入，明确AI精确执行的任务边界

**简化提问模板**：
```
基于实施规划的输入[简述核心测试计划内容]，帮我进行AI精确执行：
1. 实施规划输入包含哪些关键信息？如何解读？
2. 任务执行阶段的AI精确执行职责是什么？
3. 哪些内容属于实施规划阶段，哪些属于AI精确执行？

请明确AI精确执行的职责边界和关键依据。
```

**2轮对话示例**：
```
第1轮：用户：基于电商用户管理系统的测试计划，明确AI精确执行职责
AI：[分析测试计划的核心要求，明确AI精确执行职责]

第2轮：用户：如何确保AI精确执行完全基于实施规划输入，不偏离职责边界？
AI：[给出具体的职责边界检查和执行原则]
```

### 第2步：TDD严格实施（2-3分钟）
**目标**：严格按照TDD流程实施，确保每个功能都遵循先写测试再实现

**核心关注点**：
```
TDD严格实施：
- "如何将[具体功能]严格按照TDD流程实施？"
- "先写测试再实现的具体步骤应该怎样执行？"

AI精确执行：
- "任务描述如何设计才能让AI精确理解和执行？"
- "成功标准和验证方法如何明确定义？"
```

### 第3步：质量验证与成果交付（2-3分钟）
**目标**：确保执行成果符合严格的质量标准和贯通流程要求

**对接验证**：
```
质量验证检查：
- "执行成果是否严格遵循了TDD流程？"
- "AI精确执行的结果是否符合实施规划输入要求？"

成果交付标准：
- "交付成果能否直接投入生产使用？"
- "如何验证执行质量的完整性和准确性？"
```

## 🚨 避免贯通流程AI精确执行陷阱

### 1️⃣ 输入理解偏差陷阱
❌ **错误做法**：忽视实施规划输入，按自己理解执行  
✅ **正确做法**：严格基于实施规划输入进行AI精确执行  

### 2️⃣ TDD流程简化陷阱
❌ **错误做法**：为了效率跳过测试先写代码  
✅ **正确做法**：严格遵循TDD流程，先写测试再实现  

### 3️⃣ AI执行不精确陷阱
❌ **错误做法**：任务描述模糊，导致AI执行偏差  
✅ **正确做法**：设计精确的任务描述，确保AI能精确理解和执行  

### 4️⃣ 质量验证表面化陷阱
❌ **错误做法**：简单检查功能可用就认为完成  
✅ **正确做法**：建立严格的质量验证和成果交付标准
