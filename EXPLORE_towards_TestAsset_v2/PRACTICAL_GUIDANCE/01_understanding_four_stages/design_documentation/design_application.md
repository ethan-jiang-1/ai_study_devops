# 设计文档实践应用 - 贯通流程AI协作+输出对接（6-8分钟）

## 🔥 TL;DR - 基于贯通流程的设计阶段实践
> **目标**：掌握基于需求输入的设计输出对接 - 确保设计能直接驱动实施规划阶段
> 
> **核心转变**：独立设计技能→贯通流程中的专业分工 / 孤立设计→输入输出严格对接
> 
> **行动**：加载需求输入 → 用3步法AI协作 → 产出可对接的设计输出

---

## 🚀 基于贯通流程的设计阶段AI协作转变

### 📊 从独立设计到贯通流程设计的AI协作跃升

#### 独立设计AI协作（错误）：
```
重点：孤立的技术方案研究和架构设计
方法：方案调研→架构设计→技术选型→独立产出
产出：设计文档（与前后阶段缺乏有机联系）
```

#### 贯通流程设计AI协作（正确）：
```
重点：基于需求输入的架构设计，为实施规划准备严格输入
方法：需求理解→职责澄清→架构输出→对接检查
产出：可直接驱动实施规划阶段的设计输出
```

### 🔍 贯通流程设计阶段的核心AI协作需求
- **需求输入理解**：准确理解需求阶段输出，明确设计约束
- **职责边界澄清**：明确设计阶段做什么、不做什么
- **架构方案设计**：基于需求输入进行技术架构设计
- **测试策略规划**：可测试性设计，为实施规划做测试准备
- **输出质量检查**：确保设计输出满足实施规划阶段输入要求

## 🛠️ 基于贯通流程的3步法设计AI协作

### 第1步：阶段职责澄清（2分钟）
**目标**：明确设计阶段在贯通流程中的职责边界和输入输出要求

**提问模板**：
```
AI，我要基于需求阶段输出进行[项目名称]的架构设计，请帮我澄清：
1. 设计阶段的核心职责是什么？应该专注哪些方面？
2. 设计阶段不应该涉及什么？（避免与实施规划阶段职责混淆）
3. 如何基于需求输入进行架构设计？关键步骤是什么？
4. 设计输出如何成为实施规划阶段的直接输入？
5. "测试策略规划"与"TDD具体实施"有什么区别？

重点：明确设计阶段在贯通流程中的专业分工定位。
```

### 第2步：技术方案研究（2-3分钟）
**目标**：基于需求输入进行技术方案分析和架构设计

**提问模板**：
```
基于需求阶段的输出[简述核心需求]，帮我进行技术架构设计：
1. 针对这些需求，有哪些主要的架构方案选择？
2. 各方案的优缺点和适用场景是什么？
3. 考虑到[项目特点]，推荐哪种架构方案？
4. 这个架构的可测试性如何？需要规划哪些测试策略？
5. 架构设计中有哪些关键决策点需要明确？

重点：确保架构设计基于需求输入，同时考虑测试策略规划。
```

### 第3步：架构输出设计（2-3分钟）
**目标**：设计能直接成为实施规划阶段输入的架构输出

**提问模板**：
```
基于刚才的架构方案，帮我设计实施规划阶段所需的输出：
1. 架构设计的核心组件和接口应该如何描述？
2. 技术选型的关键决策和理由是什么？
3. 测试策略规划：哪些是设计阶段规划的，哪些留给实施规划？
4. 这些设计输出能否直接支撑实施规划阶段的TDD转换？
5. 设计阶段的质量门禁标准是什么？

重点：确保设计输出能无缝对接实施规划阶段，支撑TDD转换。
```

- 测试策略规划是否为TDD转换做好了准备？
- 设计文档是否满足实施规划阶段的输入要求？

## 🎯 基于贯通流程的项目适应性调整

### 📊 2种典型项目的贯通流程设计适应性调整

#### 🛒 快速交付型项目（如MVP、活动页面）
**贯通流程特点**：需求变化快，设计需要支撑快速迭代的实施规划

**设计阶段适应性调整**：
```
输入输出优化：
✅ 基于需求输入快速确定核心架构，避免过度设计
✅ 技术选型偏向成熟稳定，降低实施规划阶段风险
✅ 测试策略规划重点考虑快速验证的可行性
✅ 设计输出要便于实施规划阶段的快速TDD转换

贯通流程保证：
- 确保设计决策能支撑快速的实施规划和任务执行
- 架构设计要考虑后续迭代的灵活性
- 测试策略规划要平衡覆盖度和交付速度
- 质量门禁要确保基本质量的同时不阻碍快速交付
```

#### 📊 稳定质量型项目（如金融系统、企业核心业务）
**贯通流程特点**：质量要求高，设计需要为严格的实施规划提供完备输入

**设计阶段适应性调整**：
```
输入输出优化：
✅ 基于需求输入进行详尽的架构设计，考虑各种边界情况
✅ 技术选型要有充分的风险评估和依据支撑
✅ 测试策略规划要考虑全面的质量验证要求
✅ 设计输出要包含详细的技术决策依据和约束条件

贯通流程保证：
- 确保设计输出能支撑严格的实施规划和TDD实施
- 架构设计要考虑长期维护和扩展需求
- 测试策略规划要覆盖功能、性能、安全等全方位要求
- 质量门禁要确保完整性和准确性并重
```

## 🚨 避免贯通流程设计陷阱

### 1️⃣ 职责边界混淆陷阱
❌ **错误做法**：设计阶段涉及过多实施细节  
✅ **正确做法**：明确设计阶段的职责边界，专注架构设计和测试策略规划  

### 2️⃣ 输入输出脱节陷阱
❌ **错误做法**：忽视需求输入，设计输出无法对接实施规划  
✅ **正确做法**：严格基于需求输入进行设计，确保输出能驱动实施规划  

### 3️⃣ TDD定位错误陷阱
❌ **错误做法**：设计阶段就开始具体的TDD实施  
✅ **正确做法**：设计阶段专注测试策略规划，TDD实施留给实施规划和任务执行阶段  

### 4️⃣ 质量门禁缺失陷阱
❌ **错误做法**：设计完成就直接进入下一阶段  
✅ **正确做法**：设计明确的质量门禁标准，确保设计输出质量
