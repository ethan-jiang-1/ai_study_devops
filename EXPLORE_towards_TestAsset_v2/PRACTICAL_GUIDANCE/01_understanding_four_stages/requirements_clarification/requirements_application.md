### 📊 基于贯通流程思想的AI协作转变

#### 🆚 协作理念对比
```
独立技能导向（错误）：
用户：帮我完成需求分析
AI：这里填写需求，那里填写验收标准
用户：好的，需求阶段完成了

贯通流程导向（正确）：
用户：帮我梳理需求，重点是为设计阶段准备输入
AI：需要考虑这些用户故事和验收标准...
用户：这些输出能否直接驱动设计阶段？还缺什么？
AI：还需要补充架构相关的约束条件...
用户：需求阶段的职责边界在哪里？不应该涉及什么？
```

#### 🎯 贯通流程AI协作目标
- **输入输出导向**：始终考虑阶段间的严格依赖关系
- **职责边界清晰**：明确需求阶段做什么、不做什么
- **质量门禁意识**：确保输出质量达到进入下一阶段的标准
- **TDD正确定位**：理解需求阶段只涉及验收标准可测试性

## 🔍 基于贯通流程的3步法AI协作

### 第1步：阶段职责澄清（2分钟）
**目标**：明确需求阶段的职责边界和输出要求

**提问模板**：
```
AI，我要梳理[项目名称]的需求，基于软件开发贯通流程的理念：
1. 需求阶段的核心职责是什么？应该专注于哪些方面？
2. 需求阶段不应该涉及什么？（避免职责混淆）
3. 需求阶段的输出如何成为设计阶段的输入？
4. "验收标准可测试性"与"测试实施"有什么区别？

请帮我明确需求阶段在整个贯通流程中的定位。
```

### 第2步：用户故事梳理（2-3分钟）
**目标**：基于贯通流程思想，梳理清晰的用户故事

**提问模板**：
```
基于[项目名称]，帮我梳理核心用户故事：
1. 主要用户角色有哪些？每个角色的核心需求是什么？
2. 用户故事如何描述？请用"作为...我希望...以便..."格式
3. 哪些是核心功能？哪些是扩展功能？
4. 用户故事之间有什么依赖关系？

重点：专注业务需求理解，不涉及技术实现细节。
```

### 第3步：验收标准设计（2-3分钟）  
**目标**：设计可测试的验收标准，为设计阶段准备输入

**提问模板**：
```
基于刚才梳理的用户故事，帮我设计验收标准：
1. 每个用户故事的验收标准应该如何描述？
2. 如何确保验收标准是"可测试的"？
3. 这些验收标准能否直接成为设计阶段的输入？
4. 需求阶段的质量门禁标准是什么？

重点：专注验收标准的可测试性，不涉及具体测试实施方法。
```

## 💡 贯通流程AI协作最佳实践

### 🚀 基于职责边界的提问策略

#### 1️⃣ 职责明确化提问
```
❌ 职责混淆："帮我完成需求分析，包括技术选型"
✅ 职责清晰："帮我梳理用户需求和验收标准，不涉及技术实现"
```

#### 2️⃣ 输出导向提问  
```
❌ 孤立完成："帮我分析需求"
✅ 贯通导向："帮我分析需求，确保输出能直接成为设计阶段的输入"
```

#### 3️⃣ 质量门禁提问
```
第1层：需求是否清晰完整？
第2层：验收标准是否可测试？
第3层：输出是否满足进入设计阶段的条件？
```

### 🔧 需求阶段专属AI能力组合
```
专业组合：用户故事梳理+验收标准设计+输出质量检查
- AI协助用户故事场景分析
- AI协助验收标准可测试性设计
- AI协助检查需求输出的完整性和可追溯性
```

## 🎯 基于贯通流程的项目适应性调整

### 📊 2种典型项目的需求阶段适应性对比

#### 🛒 快速交付型项目（如MVP、活动页面）
**贯通流程特点**：需求变化快，设计和实施需要高度灵活性

**需求阶段适应性调整**：
```
输入输出优化：
✅ 用户故事要简洁明确，避免过度细化
✅ 验收标准要突出核心价值，容许细节调整
✅ 为设计阶段准备的输出要便于快速迭代

贯通流程保证：
- 确保需求输出能支撑快速设计决策
- 验收标准设计要考虑快速验证的可能性
- 质量门禁要平衡完整性和交付速度
```

#### 📊 稳定质量型项目（如金融系统、企业核心业务）
**贯通流程特点**：质量要求高，后续阶段需要严格的依据支撑

**需求阶段适应性调整**：
```
输入输出优化：
✅ 用户故事要详尽完整，考虑各种边界情况
✅ 验收标准要精确可验证，支持严格的质量控制
✅ 为设计阶段准备的输出要包含详细的约束条件

贯通流程保证：
- 确保需求输出能支撑严格的设计论证
- 验收标准设计要考虑合规性和审计要求
- 质量门禁要确保完整性和准确性并重
```
