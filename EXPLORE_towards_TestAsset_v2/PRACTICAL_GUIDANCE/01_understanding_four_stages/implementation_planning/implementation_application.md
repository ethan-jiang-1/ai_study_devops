## 🔍 3步法AI智能规划协作流程

### 第1步：项目阶段设计（2-3分钟）
**目标**：快速分解项目为可管理的执行阶段

**简化提问模板**：
```
请帮我分析项目[具体项目名称]的实施规划：
1. 主要执行阶段如何划分？
2. 每个阶段的核心交付物是什么？
3. 关键里程碑和时间节点怎么设置？

请简洁分析，重点突出执行重点。
```

**2轮对话示例**：
```
第1轮：用户：请分析电商用户管理系统实施规划的阶段划分
AI：[提供3-4个主要阶段的简洁分析]

第2轮：用户：对于3人团队6周时间，你推荐怎样的里程碑设置？
AI：[给出具体的时间安排建议]
```

### 第2步：任务分解与依赖（2-3分钟）
**目标**：深入理解关键任务和依赖关系

**核心关注点**：
```
任务分解：
- "请将[选定阶段]分解为具体的执行任务"
- "这些任务的执行顺序和依赖关系是什么？"

风险和资源：
- "主要的执行风险在哪里？"
- "资源配置需要注意什么关键点？"（30%强度测试思维体现）
```

### 第3步：执行策略确定（2-3分钟）
**目标**：确定最终执行策略和监控机制

**实施决策**：
```
执行策略：
- "基于项目特点，推荐的执行策略是什么？"
- "如何设计进度监控和质量控制机制？"

下一步行动：
- "第一阶段应该从什么开始？"
- "需要重点关注的成功要素有哪些？"
```

```

- 开发时间压缩25%

- 性能要求提高50%

请提供具体的调整策略和风险评估。"
```

```
质量评估提问：
"请从以下维度评估这个实施规划的质量：
1. 可执行性：任务是否具体可操作
2. 完整性：是否遗漏重要工作
3. 现实性：时间估算是否合理
4. 灵活性：能否应对常见变化
5. 可监控性：执行过程是否可控

并提出改进建议。"
```

## 🎯 项目适应性调整：类型驱动的规划策略

### 📊 2种典型项目的规划调整

#### 🚀 快速交付型项目（MVP、原型验证）
**项目特征**：
- 时间要求紧迫，重点验证核心功能
- 团队规模小，快速迭代
- 技术债务可控积累

**规划重点调整**：
```
核心关注点：
✅ 最小可行功能集的精准定义
✅ 快速迭代和用户反馈机制
✅ 时间盒管理和功能裁剪策略
✅ 技术债务的有意识控制

规划策略特色：
- 原型先行：用原型验证关键假设
- 功能聚焦：只实现最核心功能
- 快速部署：自动化部署流程
- 迭代优化：基于反馈快速调整

监控重点调整：
- 功能交付速度：每周可用功能交付
- 用户价值验证：真实用户使用反馈
- 技术债务控制：代码质量基本监控
```

#### 🏗️ 稳定质量型项目（企业系统、关键业务）
**项目特征**：
- 质量要求高，稳定性关键
- 长期维护需求，多方约束条件
- 完善的文档和知识管理需求

**规划重点调整**：
```
核心关注点：
✅ 完善的质量保证和测试策略
✅ 详细的文档和知识管理体系
✅ 风险预防和应急响应机制
✅ 渐进式上线和版本管理

规划策略特色：
- 阶段门禁：严格的质量检查机制
- 文档驱动：完整的设计和操作文档
- 冗余设计：关键环节的备选方案
- 分阶段发布：灰度发布和回滚机制

监控重点调整：
- 质量指标：代码覆盖率、缺陷密度
- 系统稳定性：可用性、性能表现
- 合规检查：安全、审计要求满足
```

## 🚨 避免实践应用陷阱

### 1️⃣ AI规划依赖陷阱
❌ **错误做法**：完全依赖AI的规划建议  
✅ **正确做法**：基于项目实际情况做独立判断  

### 2️⃣ 过度规划复杂度陷阱
❌ **错误做法**：认为规划越复杂越专业  
✅ **正确做法**：选择适合项目复杂度的规划深度  

### 3️⃣ 执行监控忽视陷阱
❌ **错误做法**：只关注规划制定，忽视执行验证  
✅ **正确做法**：规划阶段就考虑如何监控执行效果  

### 4️⃣ 静态规划陷阱
❌ **错误做法**：规划一旦制定就不允许调整  
✅ **正确做法**：建立规划的动态调整和优化机制
