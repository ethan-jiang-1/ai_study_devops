## 🔍 7步法AI智能规划协作流程

### 第1步：项目目标分解（3-4分钟）
**目标**：将项目目标分解为可管理的阶段和里程碑

**协作模板**：
```
请帮我分析项目[具体项目名称]的实施规划，包括：
1. 基于项目目标的主要阶段划分
2. 每个阶段的核心交付物和验收标准
3. 阶段间的逻辑依赖关系
4. 关键里程碑和时间节点设置
5. 与我的项目约束([时间限制/团队规模/技术栈])的匹配分析

请用结构化的方式展示，重点说明阶段划分的逻辑。
```

**实际对话示例**：
```
用户：请帮我分析电商用户管理系统的实施规划，包括阶段划分、交付物、依赖关系和里程碑，考虑3人团队、6周时间的约束。

AI：[提供详细的阶段分解分析]

用户：为什么要把用户认证和用户信息管理分成两个阶段？依赖关系是什么？
```

### 第2步：智能任务设计（3-4分钟）
**目标**：将阶段目标转化为具体可执行的任务列表

**智能设计策略**：
```
任务粒度设计：
- "请将[某个阶段]细分为1-4小时可完成的具体任务"
- "每个任务需要明确输入、处理、输出"
- "任务描述要具体到可以直接执行"

任务属性定义：
- "为每个任务定义优先级和紧急程度"
- "标识哪些任务可以并行，哪些必须串行"
- "估算每个任务的工作量和所需技能"

任务验证机制：
- "每个任务如何验证完成质量？"
- "任务完成的具体标准是什么？"
```

### 第3步：依赖关系分析（2-3分钟）
**目标**：深度分析任务间依赖，识别关键路径

**依赖分析维度**：
```
技术依赖分析：
- "这些任务在技术实现上有什么依赖关系？"
- "哪些技术选择会影响后续任务的执行？"
- "如何最小化技术依赖带来的风险？"

资源依赖分析：
- "哪些任务需要相同的人员或工具？"
- "资源冲突时如何优化调度？"
- "关键资源不可用时的备选方案？"

业务依赖分析：
- "哪些任务需要外部确认或审批？"
- "业务决策延迟时如何调整执行序列？"
```

### 第4步：风险评估识别（2-3分钟）
**目标**：全面识别执行风险并制定应对策略

**风险识别框架**：
```
执行风险：
- "每个任务执行可能遇到什么技术困难？"
- "时间估算可能存在什么偏差？"
- "团队技能不足的风险在哪里？"

协作风险：
- "团队协作可能出现什么问题？"
- "沟通不畅可能导致什么后果？"
- "角色职责不清可能在哪些环节出现？"

外部风险：
- "依赖的外部服务或资源有什么风险？"
- "需求变更的可能性和影响范围？"
- "环境或工具故障的应对预案？"
```

### 第5步：资源配置规划（2-3分钟）
**目标**：优化人员、工具、环境等资源的配置

**资源规划策略**：
```
人员配置优化：
- "基于任务技能要求，如何分配团队成员？"
- "如何平衡每个人的工作负载？"
- "关键人员不可用时的应急方案？"

工具环境规划：
- "执行这些任务需要哪些开发和测试工具？"
- "环境搭建和配置的时间成本如何？"
- "工具学习成本如何在规划中体现？"

时间资源管理：
- "如何为不确定性预留缓冲时间？"
- "哪些任务可以通过并行执行节省时间？"
- "时间压力下的任务优先级如何调整？"
```

### 第6步：执行监控策略设计（2-3分钟）🔥30%强度体现
**目标**：设计规划执行的监控、验证和调整机制

**监控策略设计**：
```
进度监控机制：
- "如何跟踪每个任务的执行进度？"
- "进度偏差的预警机制如何设计？"
- "里程碑验证的具体方法是什么？"

质量监控机制：
- "如何确保每个任务的交付质量？"
- "质量问题的早期识别方法？"
- "质量不达标时的回退和修复机制？"

协作效果监控：
- "如何评估团队协作的效果？"
- "沟通问题如何及时发现和解决？"
- "团队士气和效率的监控指标？"

风险监控机制：
- "识别的风险如何持续跟踪？"
- "风险发生时的应急响应流程？"
- "风险应对效果如何评估？"
```

### 第7步：规划优化整合（2-3分钟）
**目标**：基于前面的分析，优化并确定最终实施规划

**优化整合策略**：
```
规划优化：
- "综合考虑所有因素，如何优化这个实施规划？"
- "哪些环节可以简化？哪些地方需要加强？"
- "如何平衡进度、质量、资源这些因素？"

执行策略建议：
- "推荐的执行策略和关键成功要素？"
- "第一个里程碑应该关注哪些重点？"
- "遇到重大问题时的决策机制？"

持续改进机制：
- "如何基于执行结果持续优化规划能力？"
- "团队学习和能力提升如何融入规划？"
- "规划方法本身如何迭代改进？"
```

## 🎯 项目适应性调整：类型驱动的规划策略

### 📊 4种典型项目类型的规划调整

#### 🚀 快速交付型项目（MVP、原型验证）
**项目特征**：
- 时间要求紧迫，质量要求相对宽松
- 重点验证核心功能和业务价值
- 团队规模小，决策链短

**规划重点调整**：
```
核心关注点：
✅ 最小可行功能集的精准定义
✅ 快速迭代和反馈机制设计
✅ 技术债务的可控积累策略
✅ 用户反馈的快速收集和处理

规划策略特色：
- 时间盒管理：严格控制每个迭代周期
- 功能裁剪：大胆削减非核心功能
- 原型先行：用原型验证关键假设
- 快速部署：自动化部署和测试流程

监控重点调整：
- 功能交付速度：每周交付可用功能
- 用户反馈质量：真实用户的使用反馈
- 技术债务累积：代码质量指标监控
- 团队状态：高强度工作下的团队健康
```

#### 🏗️ 稳定质量型项目（企业系统、关键业务）
**项目特征**：
- 质量要求高，稳定性和安全性关键
- 多方面约束条件复杂
- 长期维护和演进需求

**规划重点调整**：
```
核心关注点：
✅ 完善的质量保证体系设计
✅ 详细的测试策略和验证机制
✅ 充分的文档和知识管理
✅ 风险预防和应急响应机制

规划策略特色：
- 阶段门禁：每个阶段严格质量检查
- 冗余设计：关键环节的备选方案
- 文档驱动：完整的设计和操作文档
- 渐进式上线：分阶段灰度发布

监控重点调整：
- 质量指标：代码覆盖率、缺陷密度
- 稳定性指标：系统可用性、性能表现
- 合规性检查：安全、审计要求的满足
- 知识传承：团队技能和文档完善度
```

#### 🔬 创新探索型项目（新技术、研发项目）
**项目特征**：
- 技术不确定性高，创新要求强
- 学习和试错是重要组成部分
- 成功标准可能在过程中调整

**规划重点调整**：
```
核心关注点：
✅ 技术调研和验证的时间预留
✅ 试错成本的控制和学习机制
✅ 灵活的目标调整和pivot机制
✅ 创新成果的沉淀和复用

规划策略特色：
- 探索式规划：阶段性目标+灵活调整
- 原型驱动：快速原型验证技术假设
- 学习导向：失败也是有价值的学习
- 知识沉淀：经验和教训的系统化整理

监控重点调整：
- 技术进展：关键技术难点的突破
- 学习效果：团队技能和知识的积累
- 创新质量：解决方案的创新程度
- 可复用性：成果对后续项目的价值
```

#### 👥 团队协作型项目（多团队、跨部门）
**项目特征**：
- 多方协作复杂度高
- 沟通协调成本占比大
- 依赖关系管理关键

**规划重点调整**：
```
核心关注点：
✅ 清晰的角色职责和接口定义
✅ 高效的沟通协调机制设计
✅ 依赖关系的可视化管理
✅ 冲突解决和决策机制

规划策略特色：
- 接口先行：明确定义团队间接口
- 并行开发：最大化并行工作机会
- 定期同步：高频的协调和对齐机制
- 冲突预案：预设的冲突解决流程

监控重点调整：
- 协作效率：跨团队任务的完成效率
- 沟通质量：信息传递的准确性和及时性
- 依赖管理：依赖项的交付和质量
- 团队满意度：各团队的协作体验
```

我的项目执行策略选择：

辅助策略：[如果需要，选择辅助的执行模式]
策略调整点：[相比标准策略的特殊调整]

## 🚨 避免实践应用陷阱

### 1️⃣ AI规划依赖陷阱
❌ **错误做法**：完全依赖AI的规划建议  
✅ **正确做法**：基于项目实际情况做独立判断  

### 2️⃣ 过度规划复杂度陷阱
❌ **错误做法**：认为规划越复杂越专业  
✅ **正确做法**：选择适合项目复杂度的规划深度  

### 3️⃣ 执行监控忽视陷阱
❌ **错误做法**：只关注规划制定，忽视执行验证  
✅ **正确做法**：规划阶段就考虑如何监控执行效果  

### 4️⃣ 静态规划陷阱
❌ **错误做法**：规划一旦制定就不允许调整  
✅ **正确做法**：建立规划的动态调整和优化机制
