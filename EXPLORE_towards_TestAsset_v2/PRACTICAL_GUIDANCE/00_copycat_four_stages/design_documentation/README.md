# 设计文档阶段 - 照猫画虎指南

## 🎯 本阶段目标

**明确"怎么测"** - 通过设计文档制定测试策略和测试方法

本阶段基于需求澄清的成果，设计具体的实现方案，更重要的是：**设计如何测试验证这个实现方案**。

**时间预期**：8-10分钟完成模板填写

## 🎪 阶段核心价值

### 为什么设计文档如此重要？
```
需求明确 → 设计混乱 → 实现困难 → 测试盲目 → 质量无保障
需求明确 → 设计清晰 → 实现顺畅 → 测试有序 → 质量可控
```

### 本阶段如何服务测试计划？
- **制定测试策略**：确定采用什么测试方法和测试层次
- **设计测试架构**：明确测试环境、测试工具、测试数据需求
- **识别测试重点**：基于设计复杂度确定测试重点和难点
- **规划测试接口**：设计便于测试的接口和验证点

## 🧭 设计思维导向

### 非技术化设计原则 ⭐
**重要**：本阶段避免展示具体代码，而是：
- 用**业务流程图**描述逻辑关系
- 用**自然语言**描述技术实现
- 用**AI指令**替代技术细节
- 用**测试视角**验证设计合理性

### 跨角色协作重点
- **产品经理**：确认设计满足业务需求
- **开发人员**：评估技术实现可行性
- **测试人员**：确认设计便于测试验证
- **运维人员**：评估部署和监控要求

## 🚀 快速使用流程

### 第一次使用（推荐步骤）
1. **Review需求文档**：确保清楚理解上一阶段的需求和验收标准
2. **打开设计模板**：[design_template_fill.md](./design_template_fill.md)
3. **填写核心设计**：重点描述输入-处理-输出的业务流程
4. **AI研究最佳实践**：使用[ai_research_solutions.md](./ai_research_solutions.md)获取设计参考
5. **制定测试策略**：使用[test_strategy_copycat.md](./test_strategy_copycat.md)
6. **跨角色确认**：与团队成员确认设计方案的合理性

### 🤖 AI协作重点

#### 这个阶段如何使用AI？
- **方案研究**：搜索类似功能的设计方案和最佳实践
- **架构分析**：分析不同设计方案的优缺点
- **测试策略生成**：基于设计复杂度生成测试策略
- **风险识别**：识别设计中的潜在风险和测试重点

#### AI协作原则
- **研究导向**：重点用AI研究和分析，而非直接生成设计
- **多方案对比**：让AI提供多个方案选项，人来做最终选择
- **测试视角**：每个设计决策都要考虑"这样设计如何测试"
- **非技术表达**：要求AI用业务语言解释技术概念

## ✅ 完成检查清单

### 必须完成的项目
- [ ] **业务流程设计**：用流程图或文字清楚描述业务处理流程
- [ ] **数据流设计**：明确数据如何在系统中流转和处理
- [ ] **接口设计**：定义输入输出接口和数据格式
- [ ] **异常处理设计**：设计各种异常情况的处理方式
- [ ] **测试策略制定**：明确采用什么测试方法验证设计

### 质量检查标准
- [ ] **逻辑完整性**：设计能够完整实现所有需求
- [ ] **流程清晰性**：任何团队成员都能理解业务流程
- [ ] **可测试性**：设计提供了足够的测试验证点
- [ ] **可实现性**：在当前技术条件下可以实现

### 测试导向检查
- [ ] **测试层次明确**：知道在哪些层次进行测试（单元、集成、系统）
- [ ] **测试策略合理**：基于设计复杂度制定了合适的测试策略
- [ ] **测试接口设计**：设计了便于测试的接口和验证点
- [ ] **测试数据规划**：明确了测试需要的数据类型和来源

## 🚨 新手常见错误

### ❌ 错误做法
1. **过度技术化**：直接写代码或详细技术实现
2. **忽略测试设计**：只关注功能实现，不考虑如何测试
3. **设计过于复杂**：第一次就想做完美的架构设计
4. **缺乏异常考虑**：只设计正常流程，忽略异常处理
5. **跳过方案研究**：完全凭感觉设计，不参考最佳实践

### ✅ 正确做法
1. **业务语言表达**：用流程图和自然语言描述设计
2. **测试优先思考**：每个设计决策都考虑"如何测试验证"
3. **简单有效设计**：优先选择简单、可测试的设计方案
4. **全面异常处理**：为每种异常情况设计处理方式
5. **充分研究参考**：使用AI研究行业最佳实践

## 🔧 实用技巧

### 设计文档的黄金法则
1. **输入-处理-输出思维**：任何功能都可以分解为这三个部分
2. **测试验证点设计**：在关键环节设计验证点，便于测试
3. **异常处理优先**：先设计异常处理，再设计正常流程
4. **简单性原则**：能用简单方案就不用复杂方案
5. **可观测性设计**：设计日志、监控点，便于问题诊断

### AI协作技巧
```markdown
好用的AI Prompt模板：

我需要设计[具体功能名称]功能，需求如下：
[粘贴需求文档关键内容]

请帮我：
1. 分析这类功能的常见设计模式和最佳实践
2. 提供2-3个不同的设计方案选项
3. 分析每个方案的优缺点和测试难易程度
4. 推荐最适合的测试策略和验证方法

要求用业务语言表达，避免技术细节，重点说明如何验证设计的正确性。
```

## 🌟 设计思维要点

### 从测试角度看设计
每个设计决策都要问：
- **如何验证**：这个设计如何测试验证？
- **观测点在哪**：如何知道这部分工作正常？
- **异常怎么办**：出现问题时如何发现和处理？
- **边界在哪里**：正常和异常的边界如何界定？

### 跨角色协作视角
设计文档要让每个角色都能：
- **产品经理**：确认业务流程正确，用户体验合理
- **开发人员**：理解实现要求，评估技术可行性
- **测试人员**：制定测试策略，设计测试用例
- **运维人员**：规划部署方案，设计监控策略
