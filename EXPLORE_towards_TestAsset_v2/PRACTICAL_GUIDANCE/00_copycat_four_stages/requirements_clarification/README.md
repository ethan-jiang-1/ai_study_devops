# 需求澄清阶段 - 照猫画虎指南

## 🎯 本阶段目标

**明确"测什么"** - 通过需求澄清确定测试范围和验收标准

本阶段是四阶段流程的起点，通过模板填空的方式快速明确：
- 用户真正需要什么功能
- 功能成功的标准是什么  
- 如何验证功能是否正确实现

**时间预期**：5-8分钟完成模板填写

## 🎪 阶段核心价值

### 为什么需求澄清如此重要？
```
需求不清 → 设计偏差 → 实现错误 → 测试无效 → 返工重做
需求明确 → 设计准确 → 实现正确 → 测试有效 → 一次成功
```

### 本阶段如何服务测试计划？
- **确定测试范围**：明确哪些功能需要测试，哪些不需要
- **定义验收标准**：为每个功能点制定可量化的成功标准
- **识别测试场景**：从用户需求中提取关键测试场景

### 🤖 AI协作重点

#### 这个阶段如何使用AI？
- **信息搜集**：搜索类似功能的常见需求和最佳实践
- **需求补全**：基于用户描述补充遗漏的需求细节
- **验收标准生成**：将业务需求转化为可测试的验收标准
- **质量检查**：检查需求的完整性和一致性

#### AI协作原则
- **AI辅助而非替代**：AI帮助搜集信息，人来做最终决策
- **具体化prompt**：给AI具体的上下文和明确要求
- **分步进行**：不要让AI一次完成所有内容
- **人工审核**：AI生成的内容必须经过人工检查

## ✅ 完成检查清单

### 必须完成的项目
- [ ] **功能描述**：用一句话说清楚这个功能是做什么的
- [ ] **用户需求**：至少描述2-3个具体的用户需求场景
- [ ] **功能边界**：明确什么在范围内，什么在范围外
- [ ] **验收标准**：每个需求都有对应的可测试验收标准
- [ ] **前置条件**：列出功能正常工作所需的前提条件

### 质量检查标准
- [ ] **清晰性**：任何团队成员读了都能理解
- [ ] **完整性**：没有明显的遗漏或模糊点
- [ ] **可测试性**：每个需求都能转化为具体测试用例
- [ ] **一致性**：需求之间没有冲突或矛盾

### 测试导向检查
- [ ] **测试范围明确**：知道要测试哪些功能点
- [ ] **验收标准量化**：知道怎样算测试通过
- [ ] **测试场景识别**：能从需求中提取测试场景
- [ ] **边界条件清楚**：知道正常、异常、边界情况的处理

## 🚨 新手常见错误

### ❌ 错误做法
1. **需求太抽象**：写了"系统要好用、快速、安全"这样的空话
2. **功能边界不清**：不知道什么在范围内，什么不在
3. **验收标准主观**：写了"用户满意"这样无法量化的标准
4. **忽略异常情况**：只考虑正常使用，不考虑错误输入
5. **跳过AI搜索**：完全靠自己想，不利用AI搜集信息

### ✅ 正确做法
1. **需求具体化**：用户登录用时<2秒，支持1000并发用户
2. **明确功能边界**：登录功能包含用户名密码验证，不包含第三方登录
3. **验收标准量化**：登录成功率>99%，响应时间<2秒
4. **考虑全场景**：正常登录、密码错误、用户不存在、网络异常
5. **充分利用AI**：搜索行业最佳实践，补充遗漏需求

## 🔧 实用技巧

### 需求澄清的黄金法则
1. **用户视角思考**：我是用户，我为什么要用这个功能？
2. **场景具体化**：不说"查询数据"，而说"根据用户ID查询个人信息"
3. **异常考虑**：每个正常场景都问"如果出错怎么办？"
4. **量化标准**：能用数字的地方尽量用数字
5. **边界明确**：明确说明什么做，什么不做
