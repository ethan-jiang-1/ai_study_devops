# AI搜索辅助 - 需求信息收集

## 🎯 使用目的

通过AI搜索快速收集需求相关信息，补充和完善需求文档，避免遗漏重要的功能点和场景。

**适用场景**：
- 对某类功能不够熟悉，需要了解行业标准
- 担心遗漏重要的需求场景
- 需要参考最佳实践和常见做法
- 想要了解类似功能的验收标准

**时间预期**：2-3分钟获取关键信息

## 🔍 AI搜索策略

### 搜索信息的类型
1. **功能标准**：这类功能通常包含哪些核心特性
2. **用户场景**：用户使用这类功能的典型场景
3. **异常处理**：常见的异常情况和处理方式
4. **性能标准**：行业内的性能和质量标准
5. **安全要求**：相关的安全性考虑

### 搜索的顺序建议
1. **先搜索功能概述**：了解这类功能的基本组成
2. **再搜索用户场景**：补充可能遗漏的使用场景
3. **然后搜索标准要求**：了解行业标准和最佳实践
4. **最后搜索常见问题**：预防常见的需求遗漏

## 🤖 实用AI提示模板

### 模板1：功能概述搜索
```
我需要设计一个[具体功能名称]功能，请帮我分析：

1. 这类功能通常包含哪些核心特性？
2. 用户使用这类功能的典型流程是什么？
3. 有哪些必须考虑的技术要求和限制？

请用简单的业务语言回答，重点关注用户需求而不是技术实现。

示例功能：[如"用户登录功能"、"数据查询功能"等]
```

### 模板2：用户场景补充
```
我正在分析[具体功能]的用户需求，已识别的场景包括：
[列出已经想到的场景]

请帮我补充：
1. 还有哪些重要的使用场景可能被遗漏？
2. 哪些异常情况需要特别考虑？
3. 不同类型用户使用时有什么差异？

目标是确保需求分析的完整性，避免后期返工。
```

### 模板3：标准和最佳实践
```
对于[具体功能类型]，请提供：

1. 行业标准的性能要求（如响应时间、并发量等）
2. 常见的安全性要求和考虑事项
3. 用户体验方面的最佳实践
4. 质量评估的关键指标

请提供具体的数字标准和可量化的指标。

功能背景：[简要描述功能用途和使用环境]
```

### 模板4：问题预防搜索
```
基于以下需求描述：
[粘贴当前的需求内容]

请帮我识别：
1. 这个需求描述中可能存在的模糊点
2. 容易被忽略的边界条件
3. 可能导致后期问题的需求缺陷
4. 需要与其他系统集成的依赖关系

目标是在需求阶段就发现和解决潜在问题。
```

## 🎪 实际使用示例

### 示例：用户登录功能需求搜索

**第一步：功能概述搜索**
```
AI提示：我需要设计一个用户登录功能，请帮我分析：
1. 用户登录功能通常包含哪些核心特性？
2. 用户使用登录功能的典型流程是什么？
3. 有哪些必须考虑的技术要求和限制？

AI回答摘要：
- 核心特性：身份验证、会话管理、安全防护、错误处理
- 典型流程：输入凭据 → 验证 → 建立会话 → 跳转
- 技术要求：加密传输、安全存储、防暴力破解、会话超时
```

**第二步：场景补充搜索**
```
AI提示：我正在分析用户登录功能的需求，已识别场景：
- 正常用户名密码登录
- 密码错误处理
- 用户不存在处理

请帮我补充其他重要场景...

AI回答摘要：
- 遗忘密码场景
- 账户锁定场景  
- 多次登录失败处理
- 会话过期重新登录
- 不同设备登录管理
```

**第三步：应用到需求文档**
根据AI搜索结果，补充原始需求文档中遗漏的场景和要求。

## 🚨 使用注意事项

### ✅ 正确使用方式
1. **具体化询问**：提供具体的功能名称和背景信息
2. **分类搜索**：分别搜索功能、场景、标准等不同方面
3. **批判性思考**：不盲目采用AI建议，结合实际情况判断
4. **记录过程**：记录搜索过程和决策理由
5. **验证信息**：重要信息需要通过多个渠道验证

### ❌ 错误使用方式
1. **过于宽泛**：问"帮我写个需求文档"这样的宽泛问题
2. **完全依赖**：让AI直接生成完整需求而不经过思考
3. **不加筛选**：AI的所有建议都直接采用
4. **忽略上下文**：不考虑具体项目的特殊情况
5. **一次搜索**：只搜索一次就认为信息收集完毕

## 🔄 信息验证和整合

### 信息质量评估
收集到AI建议后，需要评估：
- **相关性**：是否与当前项目相关
- **适用性**：是否适合当前的技术环境和资源
- **必要性**：是否是当前阶段必需的功能
- **可行性**：是否在当前条件下可以实现

### 整合到需求文档
1. **补充遗漏场景**：将有价值的场景添加到需求文档中
2. **完善验收标准**：使用行业标准完善验收标准
3. **明确边界**：基于最佳实践明确功能边界
4. **更新测试场景**：补充测试场景列表

## 📊 效果评估

### 搜索效果指标
- **需求完整性提升**：搜索前后需求项目数量对比
- **场景覆盖增加**：新识别的用户场景数量
- **标准明确程度**：量化指标的增加数量
- **问题预防效果**：后续阶段发现需求问题的减少

### 持续改进
- **记录有效的搜索提示**：建立个人/团队的提示词库
- **总结搜索规律**：不同类型功能的搜索重点
- **分享搜索经验**：与团队成员分享有效做法
- **更新搜索策略**：根据效果调整搜索方法

## 🎯 与主流程集成

### 在需求澄清流程中的位置
1. **完成初始需求**：先独立完成基础需求分析
2. **AI搜索补充**：使用本文档的方法搜索补充信息
3. **整合优化**：将搜索结果整合到需求文档中
4. **质量检查**：使用完善后的需求进行质量检查

### 输出到下一阶段
- **完善的需求文档**：为设计阶段提供全面的需求基础
- **标准化的验收标准**：为测试阶段提供明确的测试目标
- **识别的风险点**：为实施阶段提供风险预警
- **行业最佳实践**：为整个项目提供参考标准
