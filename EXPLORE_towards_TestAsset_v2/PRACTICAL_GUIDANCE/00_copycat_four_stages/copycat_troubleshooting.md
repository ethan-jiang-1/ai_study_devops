# 照猫画虎阶段 - 问题解决指南

## 🎯 使用说明

本文档专门解决新手在照猫画虎阶段遇到的具体问题。按照问题类型分类，提供立即可用的解决方案。

**使用方法**：根据你遇到的具体情况，找到对应的问题类型，按照解决步骤操作。

## 🚨 通用问题解决

### ❓ "我不知道从哪里开始"

**症状**：面对模板和指导，感觉无从下手  
**原因**：缺乏具体的第一步指导  

**解决方案**：
1. **选择最简单的项目**：用户登录API（用户名+密码验证）
2. **打开需求澄清模板**：[requirements_clarification/requirements_template_fill.md](./requirements_clarification/requirements_template_fill.md)  
3. **只填写模板中的[]部分**：不要想太多，直接填空
4. **5分钟内必须开始**：设定时间限制，避免过度思考

**成功标准**：开始填写第一个[]空白

---

### ❓ "模板看起来太复杂了"

**症状**：觉得模板内容太多，不知道重点是什么  
**原因**：信息过载，没有抓住重点  

**解决方案**：
1. **只关注标有⭐的必填项**：忽略其他内容
2. **每次只处理一个[]**：不要试图一次性理解全部
3. **使用AI帮助简化**：
   ```
   我是新手，这个模板对我来说太复杂了。请帮我识别出最重要的3个必填项，
   其他的我可以暂时跳过。模板内容是：[粘贴模板内容]
   ```
4. **15分钟规则**：如果15分钟内没有填写完成，说明选择的项目太复杂

**成功标准**：能识别出3个最重要的必填项

---

### ❓ "我的项目和模板示例不一样"

**症状**：模板示例是API，但我想做Web页面/移动应用/其他类型项目  
**原因**：试图直接迁移，而不是理解模板逻辑  

**解决方案**：
1. **第一次必须选择API项目**：与模板示例保持一致
2. **理解模板逻辑而非具体内容**：
   - 需求澄清 = 明确要实现什么功能
   - 设计文档 = 明确如何实现这个功能
   - 实施规划 = 明确实现的步骤和资源
   - 任务执行 = 实际去做并验证结果
3. **掌握基础后再扩展**：完成3-5个API项目后，再尝试其他类型
4. **寻找对应的专门模板**：在后续阶段会有不同项目类型的模板

**成功标准**：能够使用API模板完成至少一个项目

## 🔍 分阶段具体问题

### 📝 需求澄清阶段问题

#### ❓ "我不知道用户需求是什么"
**症状**：面对[]用户需求描述，不知道写什么  
**原因**：没有明确的用户场景  

**解决方案**：
1. **使用标准场景**：
   - 用户登录：用户需要安全地访问系统
   - 数据查询：用户需要快速找到需要的信息  
   - 文件上传：用户需要保存图片到系统中
2. **AI辅助生成**：
   ```
   我正在做一个[具体功能]的项目，请帮我生成3个简单明确的用户需求描述，
   每个需求用一句话说明用户想要达成什么目标。
   ```
3. **从用户角度思考**：我是用户，我为什么要使用这个功能？

**成功标准**：能写出1-3个简单明确的用户需求

#### ❓ "验收标准怎么写"
**症状**：不理解什么是验收标准，怎么定义  
**原因**：缺乏测试思维

**解决方案**：
1. **简单公式**：验收标准 = 如何证明功能正确工作
2. **三个基本验收标准**：
   - 正常情况：功能按预期工作
   - 异常情况：错误输入得到正确处理
   - 边界情况：极限条件下的表现
3. **AI辅助生成**：
   ```
   对于[具体功能]，请帮我生成3个验收标准：
   1. 正常情况下如何验证功能正确
   2. 异常输入时如何验证错误处理
   3. 边界条件下如何验证系统表现
   ```

**成功标准**：能写出3个可测试的验收标准

---

### 🎨 设计文档阶段问题

#### ❓ "我不会做技术设计"
**症状**：面对架构图、数据流程等技术内容，完全不懂  
**原因**：技术背景不足

**解决方案**：
1. **使用最简单的设计**：
   - 输入：用户提供什么数据
   - 处理：系统对数据做什么操作
   - 输出：系统返回什么结果
2. **AI辅助设计**：
   ```
   我是新手，不懂复杂的技术设计。对于[具体功能]，请帮我用最简单的方式描述：
   1. 用户输入什么数据
   2. 系统做什么处理
   3. 系统输出什么结果
   不需要复杂的架构图，用文字描述即可。
   ```
3. **重点关注测试策略**：如何验证设计是否正确

**成功标准**：能清楚描述输入-处理-输出的简单流程

#### ❓ "测试策略不知道怎么制定"
**症状**：理解功能需求，但不知道如何测试  
**原因**：缺乏测试方法的基础知识

**解决方案**：
1. **三层测试策略**：
   - 单元测试：测试单个功能点
   - 集成测试：测试功能间协作
   - 用户测试：测试用户体验
2. **对应需求的测试**：每个需求对应至少一种测试方法
3. **AI辅助生成**：
   ```
   对于[具体功能]，我需要制定测试策略。请帮我设计：
   1. 需要进行哪些单元测试
   2. 需要进行哪些集成测试  
   3. 需要进行哪些用户体验测试
   请给出具体的测试场景，而不是抽象的概念。
   ```

**成功标准**：能列出3-5个具体的测试场景

---

### 📊 实施规划阶段问题

#### ❓ "任务分解不知道怎么做"
**症状**：知道要做什么，但不知道分解成哪些具体任务  
**原因**：缺乏项目管理经验

**解决方案**：
1. **标准任务分解模式**：
   - 环境准备：搭建开发和测试环境
   - 核心实现：实现主要功能逻辑
   - 测试验证：执行测试计划
   - 文档整理：整理交付文档
2. **每个任务估时1-4小时**：超过4小时需要进一步分解
3. **AI辅助分解**：
   ```
   对于[具体功能]项目，请帮我分解成4-6个具体任务，
   每个任务需要：
   1. 任务名称和具体内容
   2. 预估完成时间（1-4小时）
   3. 完成标准（如何知道任务完成了）
   ```

**成功标准**：能分解出4-6个具体可执行的任务

#### ❓ "测试计划太抽象"
**症状**：写出了测试策略，但不知道具体怎么执行  
**原因**：缺乏测试执行的具体方法

**解决方案**：
1. **测试计划具体化**：
   - 测试环境：在哪里测试
   - 测试数据：用什么数据测试
   - 测试步骤：具体的操作序列
   - 预期结果：每步应该看到什么结果
2. **一个测试场景一个计划**：不要混合多个场景
3. **AI辅助具体化**：
   ```
   我有一个测试场景：[具体场景描述]
   请帮我制定具体的测试计划，包括：
   1. 需要准备什么测试环境和数据
   2. 具体的测试操作步骤（1,2,3...）
   3. 每个步骤的预期结果
   4. 如何判断测试通过或失败
   ```

**成功标准**：能写出可直接执行的测试步骤

---

### ⚡ 任务执行阶段问题

#### ❓ "代码不会写"
**症状**：知道要实现什么，但不知道怎么编程  
**原因**：编程技能不足

**解决方案**：
1. **专注于测试执行**：这个阶段的重点是验证，而不是实现
2. **使用AI生成代码**：
   ```
   基于我的设计文档：[粘贴设计内容]
   请生成简单可运行的代码实现，要求：
   1. 使用[指定语言/框架]
   2. 代码尽量简单易懂
   3. 包含基本的错误处理
   4. 提供测试用例示例
   ```
3. **重点关注测试验证**：即使代码是AI生成的，测试必须自己执行
4. **寻求技术支持**：如果团队中有开发人员，请求协助

**成功标准**：有可运行的代码，并且能执行测试计划

#### ❓ "测试执行失败了"
**症状**：按照测试计划执行，但结果不符合预期  
**原因**：实现与设计不匹配，或测试计划有问题

**解决方案**：
1. **检查顺序**：
   - 实现是否符合设计文档
   - 测试计划是否正确理解需求
   - 测试执行是否按照计划进行
2. **简化调试**：每次只测试一个功能点
3. **记录问题**：详细记录什么失败了，预期vs实际结果
4. **AI辅助分析**：
   ```
   我的测试执行失败了：
   - 测试场景：[具体场景]
   - 执行步骤：[具体步骤]
   - 预期结果：[预期什么]
   - 实际结果：[实际发生什么]
   
   请帮我分析可能的原因，并提供解决建议。
   ```

**成功标准**：能识别问题原因并采取纠正措施

## 🤖 AI协作问题

### ❓ "AI生成的内容不符合要求"
**症状**：AI给出的内容太复杂/太简单/不相关  
**原因**：prompt不够具体或上下文不清楚

**解决方案**：
1. **改进prompt结构**：
   ```
   背景：我是新手，正在学习四阶段方法论
   当前阶段：[具体阶段名称]
   具体任务：[要完成的具体任务]
   要求：[具体要求，如简单易懂、可直接使用等]
   限制：[任何限制条件]
   
   请提供具体的[要求的内容类型]。
   ```
2. **提供完整上下文**：包含前面阶段的产出
3. **明确具体要求**：不要用"帮我"这样的模糊词汇
4. **迭代改进**：基于AI反馈调整要求

**成功标准**：AI生成的内容可以直接使用或稍作修改即可使用

### ❓ "不知道什么时候该用AI"
**症状**：有时过度依赖AI，有时又完全不用  
**原因**：没有明确的AI使用原则

**解决方案**：
1. **AI使用场景**：
   - 信息搜集：搜索相关资料和最佳实践
   - 内容生成：生成模板填空内容
   - 质量检查：检查完成度和质量
   - 问题分析：分析遇到的问题和解决方案
2. **AI不适用场景**：
   - 最终决策：人必须做最终判断
   - 质量标准：人必须定义什么是"好"的结果
   - 创意思考：需要结合具体业务场景的创新
3. **黄金原则**：AI辅助人的思考，而不是替代人的思考

**成功标准**：能合理判断什么时候使用AI，什么时候独立思考

## 🎯 完成质量问题

### ❓ "不知道是否已经完成"
**症状**：做了一些工作，但不确定是否达标  
**原因**：缺乏明确的完成标准

**解决方案**：
1. **使用模板检查清单**：每个模板都有对应的检查清单
2. **自我检查三问**：
   - 我完成了模板中所有标⭐的必填项吗？
   - 我的产出能服务于测试计划吗？
   - 我能向别人清楚解释我做了什么吗？
3. **AI质量检查**：
   ```
   请检查我的[阶段名称]产出质量：
   [粘贴你的产出内容]
   
   评估标准：
   1. 是否完成了所有必填项
   2. 内容是否清晰具体
   3. 是否有利于后续测试执行
   
   请给出具体的改进建议。
   ```

**成功标准**：能通过模板检查清单的所有必填项

### ❓ "感觉质量不够好"
**症状**：完成了要求，但觉得质量一般  
**原因**：对"好"的标准期望过高

**解决方案**：
1. **照猫画虎阶段的质量标准**：
   - 完整性：完成所有必填项 ✅
   - 可用性：能用于后续阶段 ✅
   - 清晰性：自己和他人能理解 ✅
   - **不要求**：完美、创新、高深
2. **80分原则**：照猫画虎阶段达到80分就够了
3. **迭代改进**：在后续的理解应用阶段提升质量
4. **记录改进点**：为下次实践积累经验

**成功标准**：达到基本质量要求，不追求完美

## 🔄 学习进度问题

### ❓ "进展太慢"
**症状**：感觉学习速度慢，一个阶段就要很长时间  
**原因**：追求完美或选择了太复杂的项目

**解决方案**：
1. **时间盒原则**：
   - 需求澄清：最多10分钟
   - 设计文档：最多15分钟
   - 实施规划：最多15分钟
   - 任务执行：最多30分钟
2. **简化项目**：如果超时，说明项目太复杂
3. **完成优于完美**：先快速完成，再在后续迭代中改进
4. **设置提醒**：每5分钟问自己"我在追求完美吗？"

**成功标准**：能在60分钟内完成完整的四阶段循环

### ❓ "不知道什么时候可以进入下一阶段"
**症状**：完成了照猫画虎，但不确定是否准备好进入理解应用阶段  
**原因**：缺乏阶段转换标准

**解决方案**：
1. **照猫画虎完成标准**：
   - 独立完成至少3个不同的简单项目 ✅
   - 每个项目都能在60分钟内完成 ✅
   - 能解释四阶段如何服务于测试计划 ✅
   - 掌握基础AI协作技巧 ✅
2. **准备好的信号**：
   - 开始质疑模板的适用性
   - 想要根据项目特点调整方法
   - 对某个阶段有更深入的兴趣
3. **不着急**：照猫画虎是基础，基础越扎实，后续学习越轻松

**成功标准**：满足照猫画虎完成标准，并且有学习更多的主动意愿

## 🚀 紧急救援

### 🆘 "完全卡住了，不知道怎么办"

**立即行动**：
1. **停止当前所有活动**
2. **选择最简单的示例项目**："用户登录API - 输入用户名密码，返回登录成功或失败"
3. **只做需求澄清阶段**：使用[requirements_clarification/requirements_template_fill.md](./requirements_clarification/requirements_template_fill.md)模板
4. **设定10分钟时间限制**：10分钟内必须填写完成
5. **寻求帮助**：如果还是不行，请联系技术支持或有经验的同事

**重新开始的信号**：能够在10分钟内完成需求澄清模板填写
