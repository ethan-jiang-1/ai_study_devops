## 🎪 核心理念：模仿中理解贯通流程

### 什么是"照猫画虎"式学习？
- **完全模仿**：不要创新，严格按模板填空，建立标准化习惯
- **填空练习**：看到[]就填写，每个空都是质量检查点
- **贯通流程导向**：每个阶段都问"我的输出如何成为下阶段的输入？"
- **AI协助决策**：卡住了就用AI，但人要做最终决策和质量把关

### 贯通流程的核心机制是什么？
```
🔄 贯通式软件开发流程：
需求澄清 → 需求规格文档 → [严格检查] → 设计阶段输入
设计文档 → 技术架构方案 → [严格检查] → 实施规划输入  
实施规划 → 完备测试计划 → [严格检查] → 任务执行输入
任务执行 → 通过测试代码 → [严格检查] → 项目完成

核心机制：前阶段输出=后阶段输入 + 质量门禁 + 依赖检查
```

### 为什么要强调"贯通"？
- **避免信息丢失**：每个阶段的成果都完整传递到下一阶段
- **确保质量递进**：每个阶段都有明确的质量标准和检查机制
- **支持AI精确执行**：最终的测试计划能指导AI精确实现功能
- **建立系统思维**：从第一步开始就考虑如何服务于最终目标

## 📋 四阶段贯通流程详细指南

### 📝 [阶段1：需求澄清](./requirements_clarification/)

**🤖 AI协助**：需求信息搜索 + 需求完整性检查

### 🎨 [阶段2：设计文档](./design_documentation/)

**⏰ 用时**：8分钟  
**📥 严格依赖**：requirements.md（必须来自阶段1，不得跳过）

**🤖 AI协助**：技术方案研究 + 架构可行性评估

### 📊 [阶段3：实施规划](./implementation_planning/) ⭐ **TDD转换主场**
**🎯 核心职责**：明确"测试步骤" - 将设计转换为完备的测试驱动任务计划  
**⏰ 用时**：8分钟  
**📥 严格依赖**：design.md（必须来自阶段2，不得跳过）

**🔒 质量门禁**：TDD任务格式 + 测试验证方法 + 增量构建序列  
**🤖 AI协助**：测试用例设计 + 任务依赖分析

### ⚡ [阶段4：任务执行](./task_execution/)
**🎯 核心职责**：执行测试计划 - AI精确执行测试驱动的开发任务

**📥 严格依赖**：tasks.md + requirements.md + design.md（完整上下文）  
**📤 最终输出**：通过测试的工作代码 + 执行验证报告  
**🔒 质量门禁**：一次一任务 + 基于需求验证 + 完整测试覆盖  
**🤖 AI协助**：代码生成 + 测试执行 + 结果验证

## 🚨 新手必读：避免这些错误

### ❌ 常见错误（破坏贯通流程）
1. **跳过依赖检查**：不检查上一阶段输出就开始 → 必须严格基于前阶段输出
2. **违反输入输出约束**：不按规定格式产出 → 严格按requirements.md、design.md、tasks.md格式
3. **忽略质量门禁**：匆忙推进不做检查 → 每个阶段都有明确的完成标准
4. **AI完全依赖**：让AI代替质量把关 → AI协助，人必须做最终质量确认

### ✅ 贯通流程成功做法
1. **严格依赖检查**：每个阶段开始前确认输入完整性和质量
2. **标准化输出**：严格按照requirements.md → design.md → tasks.md格式产出
3. **质量门禁把关**：每个阶段完成后必须通过质量检查才能推进
4. **测试计划导向**：从需求开始就考虑如何服务于最终的完备测试计划

## ✅ 贯通流程完成标准自检

### 单阶段质量门禁标准
- [ ] **输入依赖确认**：严格基于上一阶段的标准化输出（格式正确、内容完整）
- [ ] **输出格式标准**：产出符合下一阶段输入要求（requirements.md/design.md/tasks.md）
- [ ] **质量检查通过**：满足本阶段的具体质量标准（EARS格式/架构决策/TDD任务等）
- [ ] **AI协作有效**：AI提供了有价值的协助，但人做了最终质量确认

### 贯通流程整体标准  
- [ ] **严格依赖链条**：每个阶段都严格基于前阶段输出，无跳跃或假设
- [ ] **输出输入对接**：requirements.md → design.md → tasks.md → 代码的完整传递链
- [ ] **完备测试计划**：最终产出能指导AI精确执行的详细测试计划
- [ ] **质量递进保证**：每个阶段都有质量提升，最终交付高质量成果
