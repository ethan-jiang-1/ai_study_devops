# 实施规划阶段 - 照猫画虎指南

## 🎯 本阶段目标

**明确"测试步骤和资源"** - 制定详细的实施计划和测试执行方案

本阶段基于需求澄清和设计文档的成果，制定具体的实施计划，最重要的是：**制定详细的测试计划和执行步骤**。

**时间预期**：8-10分钟完成模板填写

## 🎪 阶段核心价值

### 为什么实施规划如此重要？
```
设计完成 → 规划混乱 → 实施无序 → 测试盲目 → 质量失控
设计完成 → 规划清晰 → 实施有序 → 测试系统 → 质量可控
```

### 本阶段如何服务测试计划？
- **制定测试计划**：详细的测试执行步骤和时间安排
- **准备测试环境**：搭建和配置测试所需的环境和工具
- **规划测试数据**：准备各种测试场景需要的数据
- **分配测试资源**：明确人员分工和责任划分

## 🧭 规划思维导向

### 非技术化规划原则 ⭐
**重要**：本阶段避免过度技术化，而是：
- 用**任务清单**描述实施步骤
- 用**AI指令**替代技术实现细节
- 用**测试检查点**确保质量控制
- 用**资源清单**明确需要的人员和工具

### 跨角色协作重点
- **产品经理**：确认实施计划满足业务时间要求
- **开发人员**：评估技术实施的工作量和依赖关系
- **测试人员**：确认测试计划的完整性和可执行性
- **运维人员**：评估环境搭建和部署要求

### 🤖 AI协作重点

#### 这个阶段如何使用AI？
- **任务分解**：将复杂的实施任务分解为具体步骤
- **工作量估算**：估算各项任务的时间和资源需求
- **风险识别**：识别实施过程中的潜在风险和依赖
- **测试计划生成**：基于测试策略生成详细测试计划

#### AI协作原则
- **具体化分解**：让AI提供具体可执行的任务步骤
- **多角度评估**：从技术、时间、资源多角度评估可行性
- **风险预警**：重点识别可能影响测试执行的风险
- **检查点设计**：为每个关键步骤设计质量检查点

## ✅ 完成检查清单

### 必须完成的项目
- [ ] **任务分解完整**：所有工作都分解为具体可执行的任务
- [ ] **时间安排合理**：每个任务都有明确的时间估算和安排
- [ ] **资源需求明确**：人员、工具、环境需求都已确定
- [ ] **测试计划详细**：测试执行步骤和验证方法都已制定
- [ ] **依赖关系清晰**：任务间的依赖和执行顺序都已明确

### 质量检查标准
- [ ] **可执行性**：每个任务都是具体可操作的
- [ ] **可验证性**：每个任务都有明确的完成标准
- [ ] **可跟踪性**：能够监控执行进度和质量
- [ ] **可调整性**：计划具有一定的灵活性应对变化

### 测试导向检查
- [ ] **测试计划完整**：覆盖了测试策略中的所有测试点
- [ ] **测试环境就绪**：测试环境搭建和配置计划明确
- [ ] **测试数据准备**：各种测试场景的数据准备计划完整
- [ ] **测试执行可控**：测试执行过程可监控和调整

## 🚨 新手常见错误

### ❌ 错误做法
1. **任务过于粗糙**：写了"开发登录功能"这样的大任务
2. **忽略测试规划**：只关注开发任务，测试计划简单粗糙
3. **时间估算不准**：完全凭感觉估算，没有分解到具体步骤
4. **资源需求不明**：不知道需要什么工具和环境支持
5. **缺少检查点**：没有设计过程中的质量控制点

### ✅ 正确做法
1. **任务具体化**：分解为1-4小时可完成的具体任务
2. **测试优先规划**：详细规划测试执行的每个步骤
3. **基于分解估时**：基于具体任务分解进行时间估算
4. **资源清单明确**：列出所有需要的工具、环境、数据
5. **质量门禁设计**：在关键节点设计质量检查和确认

## 🔧 实用技巧

### 实施规划的黄金法则
1. **自顶向下分解**：从目标到任务，从粗到细逐步分解
2. **测试驱动规划**：每个开发任务都对应测试验证任务
3. **依赖关系优先**：先处理依赖关系，再安排并行任务
4. **缓冲时间预留**：为不确定性预留20-30%的缓冲时间
5. **检查点密集**：关键路径上设置密集的质量检查点

### AI协作技巧
```markdown
好用的AI Prompt模板：

我需要实施[具体功能名称]，设计方案如下：
[粘贴设计文档关键内容]

请帮我制定实施计划：
1. 将实施工作分解为具体的任务列表（每个任务1-4小时）
2. 为每个任务估算时间并安排执行顺序
3. 识别任务间的依赖关系和关键路径
4. 为每个任务设计对应的测试验证方法
5. 识别实施过程中的潜在风险和应对措施

请用任务清单的格式输出，避免技术实现细节。
```

## 🌟 规划思维要点

### 从测试角度看规划
每个实施任务都要问：
- **如何验证**：这个任务完成了如何测试验证？
- **测试准备**：执行测试需要什么环境和数据？
- **质量标准**：什么情况下算任务合格完成？
- **风险预防**：如果出问题如何快速发现和解决？

### 跨角色协作视角
实施规划要让每个角色都能：
- **产品经理**：了解项目进度和里程碑安排
- **开发人员**：清楚自己的任务和依赖关系
- **测试人员**：明确测试计划和验证方法
- **运维人员**：了解环境和部署要求

## 🎪 规划核心框架

### 三层规划结构
1. **战略层**：项目目标和里程碑安排
2. **战术层**：阶段任务和依赖关系
3. **操作层**：具体步骤和检查点

### 四维规划要素
1. **任务维度**：做什么（What）
2. **时间维度**：什么时候做（When）
3. **资源维度**：谁来做，用什么（Who & How）
4. **质量维度**：怎样算做好（Quality）
