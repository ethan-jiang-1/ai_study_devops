# 企业级电商平台系统 - 设计文档

## 1. 项目概述

### 项目名称
企业级电商平台系统

### 设计目标
设计一个高性能、高可用、可扩展的企业级电商平台架构，
支持100万+用户，10万+商品，1万+订单/日的业务规模，
系统可用性>99.9%，支持水平扩展。

### 关联需求
- 需求文档：[requirements.md](./requirements.md)
- 主要需求：REQ-001 至 REQ-006
- 设计范围：完整的电商平台系统架构

### 设计原则
- **高可用性**：系统7×24小时稳定运行
- **高性能**：支持高并发访问和大数据量处理
- **可扩展性**：支持业务和技术的持续发展
- **安全性**：全方位的安全防护和数据保护
- **可维护性**：清晰的架构设计，便于开发和运维

### 核心服务设计

#### 服务1：用户服务(UserService)
**服务职责**：用户注册、认证、个人信息管理

**核心功能**：
- 用户注册：手机号、邮箱、第三方账号注册
- 用户认证：登录、JWT Token生成和验证
- 个人信息：用户信息查询和修改
- 企业认证：B2B用户的企业认证流程

**技术架构**：
- 框架：Spring Boot + Spring Security
- 数据库：MySQL（用户表、认证表）
- 缓存：Redis（用户Session、验证码）
- 消息队列：发送用户事件消息

**接口设计**：
```
用户服务API：
POST /api/user/register          # 用户注册
POST /api/user/login             # 用户登录
GET  /api/user/profile           # 获取用户信息
PUT  /api/user/profile           # 修改用户信息
POST /api/user/enterprise-auth   # 企业认证
```

**数据模型**：
```sql
-- 用户表
CREATE TABLE users (
    id bigint PRIMARY KEY AUTO_INCREMENT,
    email varchar(100) UNIQUE NOT NULL,
    phone varchar(20) UNIQUE,
    password varchar(255) NOT NULL,
    name varchar(50) NOT NULL,
    type enum('INDIVIDUAL', 'ENTERPRISE') NOT NULL,
    status enum('ACTIVE', 'INACTIVE', 'PENDING') NOT NULL,
    created_at timestamp DEFAULT CURRENT_TIMESTAMP,
    updated_at timestamp DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    INDEX idx_email (email),
    INDEX idx_phone (phone),
    INDEX idx_status (status)
);

-- 企业认证表
CREATE TABLE enterprise_auth (
    id bigint PRIMARY KEY AUTO_INCREMENT,
    user_id bigint NOT NULL,
    company_name varchar(200) NOT NULL,
    business_license varchar(100) NOT NULL,
    legal_person varchar(50) NOT NULL,
    auth_status enum('PENDING', 'APPROVED', 'REJECTED') NOT NULL,
    created_at timestamp DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (user_id) REFERENCES users(id),
    INDEX idx_user_id (user_id),
    INDEX idx_auth_status (auth_status)
);
```

#### 服务2：商品服务(ProductService)
**服务职责**：商品信息管理、分类管理、库存管理

**核心功能**：
- 商品管理：商品基本信息、SKU管理、价格管理
- 分类管理：多级分类体系、属性管理
- 库存管理：实时库存、库存预警、库存同步
- 搜索优化：商品搜索、推荐算法

**技术架构**：
- 框架：Spring Boot + Spring Data JPA
- 数据库：MySQL（商品表、分类表、库存表）
- 搜索引擎：Elasticsearch（商品搜索）
- 缓存：Redis（热门商品、价格缓存）
- 消息队列：库存变化事件

**接口设计**：
```
商品服务API：
GET  /api/product/list           # 商品列表
GET  /api/product/{id}           # 商品详情
POST /api/product/search         # 商品搜索
GET  /api/product/category       # 商品分类
GET  /api/product/inventory/{id} # 库存查询
PUT  /api/product/inventory/{id} # 库存更新
```

**数据模型**：
```sql
-- 商品表
CREATE TABLE products (
    id bigint PRIMARY KEY AUTO_INCREMENT,
    name varchar(200) NOT NULL,
    description text,
    category_id bigint NOT NULL,
    brand varchar(100),
    status enum('ACTIVE', 'INACTIVE', 'DELETED') NOT NULL,
    created_at timestamp DEFAULT CURRENT_TIMESTAMP,
    updated_at timestamp DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    INDEX idx_category_id (category_id),
    INDEX idx_status (status),
    INDEX idx_brand (brand)
);

-- SKU表
CREATE TABLE product_skus (
    id bigint PRIMARY KEY AUTO_INCREMENT,
    product_id bigint NOT NULL,
    sku_code varchar(50) UNIQUE NOT NULL,
    price decimal(10,2) NOT NULL,
    cost_price decimal(10,2),
    specs json,
    status enum('ACTIVE', 'INACTIVE') NOT NULL,
    created_at timestamp DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (product_id) REFERENCES products(id),
    INDEX idx_product_id (product_id),
    INDEX idx_sku_code (sku_code)
);

-- 库存表
CREATE TABLE inventory (
    id bigint PRIMARY KEY AUTO_INCREMENT,
    sku_id bigint NOT NULL,
    available_quantity int NOT NULL DEFAULT 0,
    reserved_quantity int NOT NULL DEFAULT 0,
    total_quantity int NOT NULL DEFAULT 0,
    warning_quantity int NOT NULL DEFAULT 10,
    updated_at timestamp DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    FOREIGN KEY (sku_id) REFERENCES product_skus(id),
    INDEX idx_sku_id (sku_id)
);
```

#### 服务3：订单服务(OrderService)
**服务职责**：订单创建、状态管理、支付集成

**核心功能**：
- 订单创建：购物车、订单生成、地址管理
- 支付集成：多种支付方式、支付状态同步
- 订单状态：状态流转、物流跟踪
- 售后服务：退款、退货、投诉处理

**技术架构**：
- 框架：Spring Boot + Spring State Machine
- 数据库：MySQL（订单表、订单项表）
- 缓存：Redis（购物车、订单缓存）
- 消息队列：订单事件、支付事件
- 外部接口：支付宝、微信支付、物流API

**接口设计**：
```
订单服务API：
POST /api/order/create           # 创建订单
GET  /api/order/{id}             # 订单详情
PUT  /api/order/{id}/pay         # 订单支付
PUT  /api/order/{id}/cancel      # 取消订单
GET  /api/order/list             # 订单列表
POST /api/order/refund           # 申请退款
```

**业务流程**：
```
订单状态流转：
创建订单 → 待支付 → 支付中 → 已支付 → 已发货 → 已收货 → 已完成
    ↓        ↓        ↓        ↓
   取消    超时取消    支付失败   申请退款
```

### 服务间通信设计

#### 同步通信
- **REST API**：服务间的查询和简单操作
- **gRPC**：高性能的内部服务调用
- **服务发现**：通过Nacos进行服务注册和发现

#### 异步通信
- **消息队列**：使用Kafka进行事件驱动通信
- **事件总线**：业务事件的发布和订阅
- **消息主题**：用户事件、订单事件、商品事件、支付事件

```
事件驱动架构：
用户注册 → 用户事件 → 营销服务(发送优惠券) + 分析服务(用户画像)
订单创建 → 订单事件 → 库存服务(库存扣减) + 营销服务(积分奖励)
支付完成 → 支付事件 → 订单服务(状态更新) + 分析服务(销售统计)
```

### 缓存架构设计

#### 缓存层次
- **L1缓存**：应用内缓存（Caffeine）
- **L2缓存**：分布式缓存（Redis）
- **L3缓存**：CDN缓存（静态资源）

#### 缓存策略
| 数据类型 | 缓存策略 | 过期时间 | 更新策略 |
|---------|---------|---------|---------|
| 用户信息 | Cache-Aside | 30分钟 | 数据更新时删除 |
| 商品信息 | Write-Through | 1小时 | 数据更新时刷新 |
| 库存信息 | Write-Behind | 5分钟 | 异步写入数据库 |
| 搜索结果 | Cache-Aside | 15分钟 | 定时刷新 |
