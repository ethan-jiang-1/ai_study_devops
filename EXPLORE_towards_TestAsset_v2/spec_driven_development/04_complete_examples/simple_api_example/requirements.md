# 用户管理API系统 - 需求文档

## 1. 项目基本信息

### 项目名称
用户管理API系统

### 项目目标
开发一个简单易用的用户管理API系统，支持用户注册、登录、信息管理等基本功能，
为公司内部系统提供统一的用户认证和管理服务。

### 项目背景
当前公司有多个内部系统，每个系统都有自己的用户管理功能，导致：
- 用户数据不统一，维护成本高
- 用户需要在多个系统中重复注册
- 缺乏统一的权限管理机制
- 系统间用户数据同步困难

为了解决这些问题，需要开发一个统一的用户管理API系统。

### 项目范围

**包含的功能：**
- 用户注册和登录
- 用户信息管理（查看、修改）
- 基本的权限管理（角色分配）
- 密码重置功能
- 用户状态管理

**不包含的功能：**
- 复杂的权限控制系统
- 第三方登录集成
- 用户行为分析
- 邮件通知系统
- 用户界面开发

## 2. 用户和角色定义

### 主要用户角色

| 角色名称 | 角色描述 | 主要职责 | 使用频率 |
|---------|---------|---------|---------|
| 系统管理员 | 系统的最高权限用户 | 管理所有用户、分配角色、系统配置 | 每天 |
| 普通用户 | 系统的基本用户 | 注册、登录、管理个人信息 | 每天 |
| API调用方 | 调用API的其他系统 | 通过API进行用户认证和信息获取 | 持续 |

### 用户使用场景
- **普通用户**：注册账户后登录系统，查看和更新个人信息
- **系统管理员**：管理用户账户，分配角色权限，处理用户问题
- **API调用方**：通过API接口进行用户认证、获取用户信息

## 3. 功能需求 (使用EARS格式)

### 需求1：用户注册
**需求ID：** REQ-001
**优先级：** 高
**需求描述：**
在用户需要使用系统时，未注册用户需要能够通过邮箱、密码和基本信息进行注册，以便获得系统访问权限。

**详细说明：**
- 用户填写注册表单：邮箱、密码、姓名、手机号
- 系统验证邮箱格式和唯一性
- 密码需要符合复杂度要求（8位以上，包含字母和数字）
- 注册成功后自动分配普通用户角色

**验收标准：**
- [ ] 用户能够填写完整的注册信息
- [ ] 系统能够验证邮箱格式的正确性
- [ ] 系统能够验证邮箱的唯一性
- [ ] 密码复杂度验证功能正常
- [ ] 注册成功后能够正常登录

### 需求2：用户登录
**需求ID：** REQ-002
**优先级：** 高
**需求描述：**
在用户需要访问系统时，已注册用户需要能够通过邮箱和密码登录系统，以便获得访问权限和JWT Token。

**详细说明：**
- 用户输入邮箱和密码
- 系统验证用户身份
- 登录成功后生成JWT Token
- 登录失败显示明确的错误信息
- 支持记住登录状态

**验收标准：**
- [ ] 用户能够输入正确的邮箱和密码登录
- [ ] 系统能够验证用户身份
- [ ] 登录成功后返回有效的JWT Token
- [ ] 登录失败显示"用户名或密码错误"
- [ ] Token过期时间设置为24小时

### 需求3：用户信息查询
**需求ID：** REQ-003
**优先级：** 高
**需求描述：**
在用户登录系统后，用户需要能够查看自己的个人信息，以便了解账户状态和基本信息。

**详细说明：**
- 用户通过JWT Token访问个人信息
- 返回用户的基本信息（不包含密码）
- 包含用户ID、邮箱、姓名、手机号、角色、状态等信息
- 支持管理员查看任意用户信息

**验收标准：**
- [ ] 用户能够查看自己的完整个人信息
- [ ] 返回的信息不包含密码字段
- [ ] 管理员能够查看任意用户的信息
- [ ] 无权限用户无法查看他人信息
- [ ] 信息格式标准化，字段完整

### 需求4：用户信息修改
**需求ID：** REQ-004
**优先级：** 中
**需求描述：**
在用户需要更新个人信息时，用户需要能够修改自己的姓名和手机号等可变信息，以便保持信息的准确性。

**详细说明：**
- 用户可以修改姓名、手机号
- 邮箱不允许修改（作为唯一标识）
- 修改需要当前密码验证
- 修改成功后返回更新后的信息

**验收标准：**
- [ ] 用户能够修改姓名和手机号
- [ ] 邮箱字段不允许修改
- [ ] 修改时需要输入当前密码验证
- [ ] 修改成功后返回更新后的完整信息
- [ ] 手机号格式验证正确

### 需求5：密码修改
**需求ID：** REQ-005
**优先级：** 中
**需求描述：**
在用户需要更改密码时，用户需要能够通过当前密码验证后修改密码，以便保障账户安全。

**详细说明：**
- 用户输入当前密码和新密码
- 验证当前密码正确性
- 新密码需要符合复杂度要求
- 密码修改成功后需要重新登录

**验收标准：**
- [ ] 用户能够输入当前密码和新密码
- [ ] 系统能够验证当前密码正确性
- [ ] 新密码复杂度验证功能正常
- [ ] 密码修改成功后原Token失效
- [ ] 修改成功后显示成功提示

### 需求6：用户状态管理
**需求ID：** REQ-006
**优先级：** 中
**需求描述：**
在需要管理用户访问权限时，系统管理员需要能够启用或禁用用户账户，以便控制用户的系统访问权限。

**详细说明：**
- 管理员可以设置用户状态为：正常、禁用
- 禁用用户无法登录系统
- 状态修改需要管理员权限
- 状态修改后立即生效

**验收标准：**
- [ ] 管理员能够修改用户状态
- [ ] 禁用用户无法登录系统
- [ ] 状态修改需要管理员权限验证
- [ ] 状态修改后立即生效
- [ ] 状态修改有操作日志记录

### 需求7：用户角色管理
**需求ID：** REQ-007
**优先级：** 低
**需求描述：**
在需要分配用户权限时，系统管理员需要能够为用户分配不同的角色，以便实现基本的权限控制。

**详细说明：**
- 系统支持两种角色：管理员、普通用户
- 管理员可以分配和修改用户角色
- 角色修改后立即生效
- 至少保留一个管理员账户

**验收标准：**
- [ ] 管理员能够为用户分配角色
- [ ] 支持管理员和普通用户两种角色
- [ ] 角色修改后立即生效
- [ ] 系统至少保留一个管理员账户
- [ ] 角色修改有操作日志记录
