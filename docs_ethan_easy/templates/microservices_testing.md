# 微服务架构测试模板

## 🎯 使用场景

当你的系统采用微服务架构，需要测试服务间的复杂交互时使用此模板：
- 多个服务的协同工作
- 分布式事务处理
- 服务间的数据一致性
- 故障隔离和恢复

## 💡 核心思路
这个高级提示词专注微服务复杂性：**服务协作 + 分布式事务 + 故障隔离**
- 详细描述服务间关系（同步调用、异步消息）
- 重视分布式特性（数据一致性、事务处理）
- 强调容错能力（服务降级、熔断恢复）

## 🛠️ 模板填写指南

### 微服务架构信息
- **服务数量**：通常3-20个核心服务
- **通信方式**：REST API、gRPC、消息队列
- **数据存储**：每个服务独立数据库
- **部署方式**：容器化 + 编排平台

### 常见微服务技术栈
- **Java生态**：Spring Boot + Spring Cloud + MySQL + Redis
- **Node.js生态**：Express + MongoDB + Redis + RabbitMQ
- **Go生态**：Gin + PostgreSQL + Redis + Kafka
- **.NET生态**：ASP.NET Core + SQL Server + Redis

### 典型微服务场景
- **电商平台**：用户服务、商品服务、订单服务、支付服务
- **金融系统**：账户服务、交易服务、风控服务、通知服务
- **内容平台**：用户服务、内容服务、推荐服务、评论服务

## 💡 高级使用技巧

### ✅ 提升模板效果
1. **架构图支持**：提供服务架构图更直观

### ✅ 复杂场景处理
1. **分层测试**：单服务 → 服务间 → 端到端
2. **渐进复杂**：正常场景 → 异常场景 → 极端场景
3. **重点突出**：优先测试核心业务流程
4. **风险导向**：重点关注高风险服务和交互

### ✅ 持续优化
