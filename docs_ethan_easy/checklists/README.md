# 检查清单 - 验证AI生成的测试质量

## 🎯 使用场景

当AI生成了测试方案后，不同角色的人员使用对应的检查清单来验证质量：

- **👨‍💻 程序员** → [for_developers.md](./for_developers.md)
- **👩‍💼 产品经理** → [for_pm.md](./for_pm.md)
- **👨‍💼 业务专家** → [for_business.md](./for_business.md)

## 📋 角色分工

### 👨‍💻 程序员检查重点
- **技术可行性**：能否实际实现？
- **测试覆盖**：测试是否完整？
- **代码质量**：代码是否规范？
- **风险识别**：技术风险是否可控？

### 👩‍💼 产品经理检查重点
- **业务逻辑**：业务规则是否正确？
- **用户体验**：用户使用是否便利？
- **功能完整**：功能需求是否满足？
- **产品质量**：质量标准是否达标？

### 👨‍💼 业务专家检查重点
- **业务规则**：业务规则是否准确？
- **合规性**：是否符合法规要求？
- **行业标准**：是否符合行业规范？
- **业务风险**：业务风险是否可控？

## 🚀 使用流程

### 步骤1：分工检查（并行进行）
```
程序员 → 技术可行性检查 → 技术问题清单
产品经理 → 业务逻辑检查 → 产品问题清单
业务专家 → 业务规则检查 → 业务问题清单
```

### 步骤2：汇总讨论（集中讨论）
```
各角色汇报检查结果 → 讨论问题优先级 → 确定改进方案
```

### 步骤3：改进实施（分工执行）
```
程序员优化技术方案 → 产品经理完善需求 → 业务专家澄清规则
```

## 💡 高效使用技巧

### ✅ 做这些
- **重点关注**：优先检查核心功能和高风险场景
- **记录问题**：详细记录发现的问题和改进建议
- **积极沟通**：及时与其他角色沟通澄清问题
- **持续改进**：根据使用经验优化检查清单

### ❌ 避免这些
- **越俎代庖**：不要检查其他角色的专业领域
- **过度细化**：不要纠结于非关键的细节问题
- **完美主义**：不要追求100%的完美方案
- **单兵作战**：不要独自完成所有检查工作

## 🎯 质量标准

### 检查时间建议
- **程序员检查**：30-45分钟
- **产品经理检查**：20-30分钟
- **业务专家检查**：25-35分钟

### 通过标准
- **优秀（90-100分）**：可直接开始实施
- **良好（70-89分）**：解决少量问题后可实施
- **合格（60-69分）**：需要较多改进后实施
- **不合格（<60分）**：需要重新生成测试方案

## 🔄 迭代改进

### 检查结果处理
1. **高优先级问题**：必须解决才能通过
2. **中优先级问题**：建议解决，可适当推迟
3. **低优先级问题**：可选解决，或后续改进

### 改进反馈循环
```
检查发现问题 → 优化提示词 → 重新生成测试 → 再次检查
```


---

**记住**：检查清单的目的是确保AI生成的测试方案能够真正保障产品质量。重点是发现问题、解决问题，而不是找茬。
