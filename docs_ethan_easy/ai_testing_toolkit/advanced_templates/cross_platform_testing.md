# 跨平台兼容性测试模板

## 🎯 使用场景

当你的应用需要在多个平台上运行并保持一致体验时使用此模板：
- Web应用的浏览器兼容性
- 移动应用的iOS/Android兼容性
- 桌面应用的Windows/Mac/Linux兼容性
- 跨平台框架应用（Flutter、React Native、Electron）
- 混合部署环境兼容性

## 💡 核心思路
这个高级提示词专注兼容性挑战：**一致体验 + 平台特色 + 差异处理**
- 保证核心功能在所有平台的一致性
- 充分利用各平台的特色功能
- 妥善处理平台间的技术差异

## 🛠️ 模板填写指南

### 平台优先级确定
- **主要平台**：用户量最大、收入贡献最高的平台
- **次要平台**：有一定用户基数但非核心的平台
- **实验平台**：新兴或试验性的平台
- **维护平台**：遗留但仍需支持的平台

### 兼容性等级定义
- **完全兼容**：功能和体验完全一致
- **基本兼容**：核心功能正常，体验略有差异
- **部分兼容**：部分功能可用，有明显限制
- **不兼容**：功能无法使用或严重问题

### 测试深度选择
- **全量测试**：所有功能在所有平台的完整测试
- **抽样测试**：重要功能的全平台测试
- **重点测试**：核心平台的全功能测试
- **基线测试**：基本功能的基本平台测试

## 💡 高级使用技巧

### ✅ 提升兼容性质量
1. **建立基准**：选择一个平台作为基准进行对比
2. **分层验证**：从核心功能到增强功能逐层验证
3. **自动化对比**：使用工具自动对比界面和功能差异
4. **用户验证**：邀请各平台用户参与验证测试

### ✅ 复杂场景处理
1. **平台特性映射**：将功能需求映射到各平台的实现方式
2. **降级策略**：为不支持的功能设计合理的降级方案
3. **差异管理**：建立平台差异的管理和文档化机制
4. **版本策略**：制定各平台版本发布和同步策略

### ✅ 测试效率优化
1. **优先级驱动**：基于业务价值确定测试优先级
2. **风险驱动**：重点测试高风险的兼容性问题
3. **工具辅助**：使用兼容性测试工具提升效率
4. **经验复用**：建立兼容性问题库和解决方案库

---

**记住**：跨平台兼容性测试的关键在于平衡一致性和平台特色。既要保证核心体验的一致，又要充分利用各平台的优势特性。
