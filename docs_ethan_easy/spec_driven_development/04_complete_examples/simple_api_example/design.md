# 用户管理API系统 - 设计文档

## 1. 项目概述

### 项目名称
用户管理API系统

### 设计目标
设计一个高性能、易维护、安全可靠的用户管理API系统，
支持1万用户数据，API响应时间<500ms，系统可用性>99.5%

### 关联需求
- 需求文档：[requirements.md](./requirements.md)
- 主要需求：REQ-001 至 REQ-007
- 设计范围：完整的用户管理API系统

### 设计原则
- 简单可用：API设计简洁易用，降低集成成本
- 安全可靠：数据安全，权限控制严格
- 高性能：响应速度快，支持并发访问
- 易维护：代码结构清晰，便于扩展和维护

## 3. 功能模块设计

### 模块划分
| 模块名称 | 模块职责 | 主要功能 | 接口依赖 |
|---------|---------|---------|---------|
| 用户认证模块 | 处理用户认证相关功能 | 注册、登录、Token验证 | 无 |
| 用户管理模块 | 处理用户信息管理 | 查询、修改用户信息 | 认证模块 |
| 权限管理模块 | 处理权限控制 | 角色分配、权限验证 | 认证模块 |
| 系统管理模块 | 处理系统管理功能 | 用户状态管理、日志记录 | 认证模块、权限模块 |

### 模块详细设计

#### 模块1：用户认证模块
**模块职责：** 处理用户注册、登录、Token生成和验证

**功能列表：**
- 用户注册：验证用户输入，创建用户账户
- 用户登录：验证用户身份，生成JWT Token
- Token验证：验证Token有效性，提取用户信息
- 密码加密：使用BCrypt加密用户密码

**接口设计：**
- POST /api/auth/register：用户注册
- POST /api/auth/login：用户登录
- POST /api/auth/refresh：Token刷新
- POST /api/auth/logout：用户登出

**数据模型：**
- User实体：用户基本信息
- UserRole实体：用户角色信息
- LoginRecord实体：登录记录信息

**业务流程：**
```
用户注册流程：
1. 接收用户注册信息
2. 验证邮箱格式和唯一性
3. 验证密码复杂度
4. 加密密码并保存用户信息
5. 返回注册成功结果

用户登录流程：
1. 接收用户登录信息
2. 验证用户存在性
3. 验证密码正确性
4. 生成JWT Token
5. 记录登录日志
6. 返回Token和用户信息
```

#### 模块2：用户管理模块
**模块职责：** 处理用户信息的查询和管理

**功能列表：**
- 用户信息查询：获取用户详细信息
- 用户信息修改：更新用户可变信息
- 密码修改：更新用户密码
- 用户列表查询：管理员查询用户列表

**接口设计：**
- GET /api/users/profile：获取当前用户信息
- PUT /api/users/profile：修改当前用户信息
- PUT /api/users/password：修改用户密码
- GET /api/users：获取用户列表（管理员）

**数据模型：**
- UserProfile实体：用户详细信息
- UserUpdateRequest：用户更新请求
- PasswordChangeRequest：密码修改请求

**业务流程：**
```
用户信息修改流程：
1. 验证用户身份和权限
2. 验证当前密码
3. 验证新信息格式
4. 更新用户信息
5. 返回更新后的用户信息
```

#### 模块3：权限管理模块
**模块职责：** 处理用户权限和角色管理

**功能列表：**
- 权限验证：验证用户操作权限
- 角色管理：分配和管理用户角色
- 权限拦截：拦截无权限的请求

**接口设计：**
- GET /api/roles：获取角色列表
- PUT /api/users/{id}/role：修改用户角色
- GET /api/permissions：获取权限列表

**数据模型：**
- Role实体：角色信息
- Permission实体：权限信息
- UserRole实体：用户角色关联

#### 模块4：系统管理模块
**模块职责：** 处理系统级别的管理功能

**功能列表：**
- 用户状态管理：启用/禁用用户账户
- 系统日志：记录系统操作日志
- 健康检查：提供系统健康状态接口

**接口设计：**
- PUT /api/admin/users/{id}/status：修改用户状态
- GET /api/admin/logs：获取系统日志
- GET /api/health：健康检查

## 4. 接口设计

### 接口设计原则
- RESTful设计：遵循REST架构风格
- 统一响应格式：所有接口使用统一的JSON响应格式
- 版本控制：API路径包含版本号 /api/v1/
- 安全认证：除注册和登录外，所有接口都需要JWT认证

### API接口列表
| 接口名称 | 请求方法 | 请求路径 | 功能描述 | 权限要求 |
|---------|---------|---------|---------|---------|
| 用户注册 | POST | /api/v1/auth/register | 新用户注册 | 无 |
| 用户登录 | POST | /api/v1/auth/login | 用户登录 | 无 |
| 获取用户信息 | GET | /api/v1/users/profile | 获取当前用户信息 | 登录用户 |
| 修改用户信息 | PUT | /api/v1/users/profile | 修改当前用户信息 | 登录用户 |
| 修改密码 | PUT | /api/v1/users/password | 修改用户密码 | 登录用户 |
| 获取用户列表 | GET | /api/v1/users | 获取用户列表 | 管理员 |
| 修改用户状态 | PUT | /api/v1/admin/users/{id}/status | 修改用户状态 | 管理员 |
| 修改用户角色 | PUT | /api/v1/admin/users/{id}/role | 修改用户角色 | 管理员 |

### 接口详细设计

#### 接口1：用户注册
**功能描述：** 新用户注册账户

**请求信息：**
- 方法：POST
- 路径：/api/v1/auth/register
- 参数：
  ```json
  {
    "email": "用户邮箱",
    "password": "用户密码",
    "name": "用户姓名",
    "phone": "手机号码"
  }
  ```

**响应信息：**
- 成功响应：
  ```json
  {
    "code": 200,
    "message": "注册成功",
    "data": {
      "userId": 1,
      "email": "user@example.com",
      "name": "张三",
      "phone": "13800138000",
      "role": "USER",
      "status": "ACTIVE"
    }
  }
  ```
- 失败响应：
  ```json
  {
    "code": 400,
    "message": "邮箱已存在",
    "data": null
  }
  ```

#### 接口2：用户登录
**功能描述：** 用户登录获取访问令牌

**请求信息：**
- 方法：POST
- 路径：/api/v1/auth/login
- 参数：
  ```json
  {
    "email": "用户邮箱",
    "password": "用户密码"
  }
  ```

**响应信息：**
- 成功响应：
  ```json
  {
    "code": 200,
    "message": "登录成功",
    "data": {
      "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
      "expiresIn": 86400,
      "user": {
        "id": 1,
        "email": "user@example.com",
        "name": "张三",
        "role": "USER"
      }
    }
  }
  ```

#### 接口3：获取用户信息
**功能描述：** 获取当前登录用户的详细信息

**请求信息：**
- 方法：GET
- 路径：/api/v1/users/profile
- 请求头：Authorization: Bearer {token}

**响应信息：**
- 成功响应：
  ```json
  {
    "code": 200,
    "message": "获取成功",
    "data": {
      "id": 1,
      "email": "user@example.com",
      "name": "张三",
      "phone": "13800138000",
      "role": "USER",
      "status": "ACTIVE",
      "createdAt": "2024-01-15T10:30:00Z",
      "updatedAt": "2024-01-15T10:30:00Z"
    }
  }
  ```

### 统一错误码
- 200：成功
- 400：请求参数错误
- 401：未认证或Token过期
- 403：权限不足
- 404：资源不存在
- 409：资源冲突（如邮箱已存在）
- 500：服务器内部错误

- **主数据库**：MySQL 8.0
- **缓存数据库**：Redis 6.2
- **连接池**：HikariCP
- **ORM框架**：Spring Data JPA

### 数据表设计

#### 表1：用户表 (users)
**表功能：** 存储用户基本信息

| 字段名 | 类型 | 长度 | 是否为空 | 默认值 | 说明 |
|--------|------|------|---------|--------|------|
| id | bigint | - | NOT NULL | AUTO_INCREMENT | 用户ID，主键 |
| email | varchar | 100 | NOT NULL | - | 用户邮箱，唯一 |
| password | varchar | 255 | NOT NULL | - | 加密后的密码 |
| name | varchar | 50 | NOT NULL | - | 用户姓名 |
| phone | varchar | 20 | NULL | - | 手机号码 |
| role | varchar | 20 | NOT NULL | 'USER' | 用户角色 |
| status | varchar | 20 | NOT NULL | 'ACTIVE' | 用户状态 |
| created_at | datetime | - | NOT NULL | CURRENT_TIMESTAMP | 创建时间 |
| updated_at | datetime | - | NOT NULL | CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP | 更新时间 |

**索引设计：**
- 主键：id
- 唯一索引：uk_email (email)
- 普通索引：idx_status (status)
- 普通索引：idx_created_at (created_at)

**建表语句：**
```sql
CREATE TABLE users (
    id bigint NOT NULL AUTO_INCREMENT,
    email varchar(100) NOT NULL,
    password varchar(255) NOT NULL,
    name varchar(50) NOT NULL,
    phone varchar(20) DEFAULT NULL,
    role varchar(20) NOT NULL DEFAULT 'USER',
    status varchar(20) NOT NULL DEFAULT 'ACTIVE',
    created_at datetime NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at datetime NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    PRIMARY KEY (id),
    UNIQUE KEY uk_email (email),
    KEY idx_status (status),
    KEY idx_created_at (created_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

## 6. 缓存设计

### 缓存策略
| 缓存类型 | 使用场景 | 缓存时间 | 更新策略 |
|---------|---------|---------|---------|
| 用户信息缓存 | 用户登录后缓存基本信息 | 30分钟 | 用户信息更新时主动删除 |
| Token黑名单 | 用户退出后Token失效 | Token过期时间 | 用户退出时添加 |
| 登录失败计数 | 防止暴力破解 | 15分钟 | 成功登录后删除 |

### 缓存架构
```
缓存架构：
┌─────────────┐    ┌─────────────┐    ┌─────────────┐
│   应用层     │    │   Redis     │    │   MySQL     │
│Spring Boot  │────│   缓存层     │────│   数据层     │
│             │    │             │    │             │
└─────────────┘    └─────────────┘    └─────────────┘
```

### 缓存Key设计
- 用户信息：`user:profile:{userId}`
- Token黑名单：`token:blacklist:{token}`
- 登录失败计数：`login:fail:{email}`

## 7. 安全设计

### 认证授权设计
- **认证方式**：JWT Token认证
- **Token过期时间**：24小时
- **Token刷新策略**：滑动过期（每次访问重新计算过期时间）
- **权限控制**：基于角色的访问控制(RBAC)

### 数据加密设计
- **密码加密**：使用BCrypt算法，盐值长度12
- **敏感信息**：手机号进行脱敏显示
- **传输加密**：使用HTTPS协议
- **存储加密**：敏感配置信息使用环境变量

### 安全措施
| 安全领域 | 安全措施 | 实现方式 |
|---------|---------|---------|
| 接口安全 | 防止SQL注入和XSS攻击 | 使用参数化查询，输入验证 |
| 认证安全 | 防止暴力破解 | 登录失败次数限制 |
| 数据安全 | 敏感数据保护 | 数据脱敏，加密存储 |
| 传输安全 | 通信加密 | HTTPS，安全头设置 |
