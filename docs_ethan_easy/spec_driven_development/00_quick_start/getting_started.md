## 🚀 第二步：5分钟实战演练

### 实战场景：开发一个用户登录API

#### 2.1 需求分析（2分钟）
使用需求模板，填写以下信息：

```markdown
# 用户登录API需求文档

## 1. 项目基本信息
- **项目名称**：用户登录API
- **项目目标**：为移动应用提供用户登录认证服务
- **项目背景**：现有系统缺少统一的用户认证机制

## 2. 功能需求
### 需求1：用户登录认证
**需求描述**：用户通过用户名和密码登录，系统验证后返回认证令牌
**用户场景**：移动应用用户在登录页面输入用户名密码，点击登录按钮
**验收标准**：
- 验证成功返回token和用户信息
- 验证失败返回错误信息
- 响应时间小于500ms

### 需求2：登录状态检查
**需求描述**：检查用户登录状态是否有效
**用户场景**：用户访问需要登录的页面时，系统检查登录状态
**验收标准**：
- 有效token返回用户信息
- 无效token返回401错误
- 支持token刷新机制

## 3. 非功能需求
- **性能要求**：响应时间<500ms，支持1000并发
- **安全要求**：密码加密存储，token有效期24小时
- **可用性要求**：系统可用率>99.9%
```

#### 2.2 设计方案（2分钟）
使用设计模板，快速完成架构设计：

```markdown
# 用户登录API设计文档

## 1. 设计概述
- **设计目标**：提供安全、高效的用户认证服务
- **关联需求**：需求1、需求2
- **设计原则**：安全第一、简单易用、高可用

## 2. 系统架构
- **总体架构**：RESTful API + JWT认证
- **技术选型**：Spring Boot + MySQL + Redis
- **部署架构**：Docker容器化部署

## 3. 详细设计
### 模块1：用户认证模块
- **功能描述**：处理用户登录认证
- **接口设计**：
  - POST /api/login - 用户登录
  - POST /api/logout - 用户登出
  - GET /api/user/info - 获取用户信息
- **数据设计**：用户表、登录日志表
```

## 🎉 第三步：检查你的成果

### 成果检查清单
```yaml
文档完整性检查：
□ 需求文档：目标明确，需求具体，标准清晰
□ 设计文档：架构合理，技术选型合适，设计完整
□ 任务文档：任务明确，责任清晰，时间合理

质量检查：
□ 是否解决了实际问题？
□ 是否其他人能看懂？
□ 是否可以直接执行？
□ 是否考虑了风险？
```

### 对比传统方式
```yaml
传统方式：
- 需求：口头沟通，理解不一致
- 设计：脑中构思，没有文档
- 任务：随意分工，责任不清
- 时间：边做边想，效率低下

规范化方式：
- 需求：文档化，标准化，可验证
- 设计：结构化，可评审，可复用
- 任务：明确化，可跟踪，可评估
- 时间：5分钟准备，后续执行顺畅
```

## 🔧 常见问题解决

### Q1：模板太复杂，不知道怎么填写？
```yaml
解决方案：
1. 先填写必填项，选填项可以后补
2. 参考完整示例，看看别人怎么写
3. 和团队一起讨论，集思广益
4. 从简单项目开始，逐步提高复杂度
```

### Q2：团队成员不愿意使用？
```yaml
解决方案：
1. 先自己用，证明确实有效
2. 找到支持者，形成小团队
3. 从小项目开始，降低试错成本
4. 分享成功经验，用数据说话
```

### Q3：觉得文档写得不够好？
```yaml
解决方案：
1. 先写出来，再逐步改进
2. 请同事帮忙review，提供建议
3. 学习其他优秀项目的文档
4. 持续练习，熟能生巧
```

### Q4：不知道如何评估效果？
```yaml
解决方案：
1. 记录使用前后的时间对比
2. 收集团队的主观感受
3. 统计返工和问题的次数
4. 定期回顾和总结
```
